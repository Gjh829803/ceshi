# 载具回正与 F 键优先级方案

## 目标

为所有已接入载具补充统一的状态判断和回正/脱困逻辑，并将能力接入现有的
`F` 交互键。

核心交互如下：

| 场景 | 第一次按 F | 后续按 F |
| --- | --- | --- |
| 人物靠近正常载具 | 上车 | — |
| 人物靠近翻车或卡住的载具 | 回正/脱困，不上车 | 再次按 F 上车 |
| 驾驶正常载具 | 下车 | — |
| 驾驶翻车或卡住的载具 | 回正/脱困，不下车 | 再次按 F 下车 |
| 载具实际飞行中 | 保留现有飞行交互 | 按现有飞行状态处理 |

回正或脱困失败时，当前 F 只消费本次请求并提示失败原因，不继续执行上车或
下车，避免一次按键触发两个动作。

## 当前基础

SDK 当前已经具备以下能力：

- `HumanoidRuntime.recoverVehicle()` 和 `vehicle.recover` 命令；
- 车辆安全地面搜索、支撑采样、障碍扫掠、净空检查；
- 速度、角速度清零以及轮胎/刚体状态重建；
- 90°、180°、270° 翻车回正测试；
- F 作为统一 `interact` 输入，驾驶中的 F 当前会进入原有下车/交互流程。

本需求主要补齐三部分：

1. 统一的载具运行状态和回正候选判定；
2. 徒步时回正附近载具的能力；
3. F 交互中“回正/脱困优先于上车或下车”的分发规则。

## 状态模型

状态不能只使用 `grounded`，也不能根据载具是否属于飞机来判断是否正在飞行。
建议新增 SDK 内部统一状态判定，并让运行时、诊断和 Playground HUD 共用它。

```ts
type VehicleCondition =
  | 'normal'
  | 'flipped'
  | 'stuck'
  | 'airborne'
  | 'not-applicable';

type VehicleRecoveryReason =
  | 'flipped'
  | 'blocked'
  | 'flipped-and-blocked'
  | null;
```

`airborne` 是当前物理状态，不代表载具具备飞行能力。飞机已经落地、停在跑道
上、侧翻或倒扣时，不再属于 `airborne`，应继续参与地面姿态判断。

`not-applicable` 用于暂不支持这套回正/脱困动作的载具类型或介质状态，例如
当前在水下且没有安全回正规则的载具。它不是失败状态，也不应覆盖现有的专属
交互逻辑。

### 翻车判定

翻车判定建议使用以下事实的组合，而不是单一阈值：

- 当前载具不是实际空中状态；
- 载具刚体或底盘存在地面/建筑接触，或已经进入落地稳定窗口；
- 载具局部 Up 与实际支撑方向/世界 Up 的夹角超过阈值；
- 姿态、角速度和位置在连续若干固定帧内满足稳定条件，避免翻滚过程中的瞬时
  姿态立即触发回正。

姿态判断要以车身刚体为准，不能只依赖轮胎接触数。飞机倒扣在跑道上时，轮子
可能没有有效接触，但机身与地面已有支撑，此时应识别为 `flipped` 而不是
`airborne`。

### 实际飞行判定

`airborne` 需要同时考虑运动家族的实际阶段和物理接触：

- 飞行载具正在起飞、巡航、俯冲、滑翔或着陆过渡，且没有稳定地面支撑时，判为
  `airborne`；
- 载具虽然是飞机，但已经与地面、屋顶或其他静态结构稳定接触时，退出
  `airborne`；
- 载具从空中落地后的短暂弹跳期间保留落地缓冲，不立即按翻车处理；
- 普通汽车从坡面起跳或短暂离地时，也不应因为 `grounded=false` 自动变成翻车。

因此，“飞机”是能力类型，“飞行中”是当前状态，两者必须分开。

### 卡住/脱困判定

`stuck` 用于处理载具没有翻倒、但已经卡进建筑、墙体、障碍物或地形边缘的
情况。判定需要避免把普通停车误判为卡住，建议至少同时满足：

- 通常不在 `airborne`、过渡动画或明确的下水/着陆流程中；但飞机/旋翼机若持续有
  驾驶输入、速度和位移都接近 0，即使碰撞代理仍把它标成空中，也按“疑似穿透/卡死”
  累计阻挡时间，避免模型穿进建筑后永远没有脱困入口；
- 驾驶者持续给出前进、后退或转向意图；
- 驱动系统有实际输出，或刚体存在持续的阻挡接触/重叠迹象；
- 在固定时间窗口内，车辆的有效位移和速度均低于阈值；
- 不是主动刹车、没有输入、动力关闭或正常停驻。

判定应使用连续固定帧和滞回：进入 `stuck` 需要持续阻挡一段时间，恢复为
`normal` 则需要观察到有效位移或驾驶意图释放。诊断失败时宁可不提供脱困提示，
不要把正常停车误判为卡住。

### 回正候选与可执行性

状态判定和动作可执行性分开：

- `condition` 描述当前事实；
- `recoveryAvailable` 描述当前是否已经找到安全回正/脱困方案；
- `recoveryReason` 描述为什么需要回正；
- 地面、坡度、障碍、净空或介质不满足时，状态仍可以是 `flipped`/`stuck`，但
  `recoveryAvailable=false`。

这样可以正确表达“确实翻车了，但当前位置没有足够空间回正”。

## 回正与脱困执行

保留现有安全检查和单一物理写入者原则，扩展回正方法以支持当前驾驶者和附近
目标两种模式：

```ts
recoverVehicle(): boolean;
recoverVehicle(targetInstanceId: string): boolean;
```

### 驾驶中

- 目标固定为当前驾驶载具；
- 翻车时恢复为保持当前水平朝向的直立姿态；
- 卡住时优先尝试当前区域的安全脱困位置；
- 必要时在有限搜索半径内寻找完整车身可放置的位置；
- 清零线速度、角速度、油门和临时动力状态；
- 重建轮胎/刚体辅助状态；
- 保留驾驶关系、相机模式、载具 ID 和当前测试场景身份。

### 徒步时

- 目标是现有最近交互范围内、状态为 `flipped` 或 `stuck` 的载具；
- 不自动上车，不移动人物；
- 回正成功后仍需再次按 F 上车；
- 如果安全搜索导致载具发生有限位移，HUD 必须重新计算距离和可交互状态。

### 安全失败

下列情况不得强行瞬移或穿透障碍：

- 没有稳定地面或当前介质不支持回正；
- 车身 footprint 采样不完整；
- 车身姿态与支撑高度差过大；
- 回正路径被墙体、建筑或低顶阻挡；
- 直立车身净空不足；
- 目标载具正在被其他人物占用。

失败只更新消息和失败原因，不改变载具、人物、驾驶关系或相机状态。

## F 键分发优先级

F 仍然是现有 `interact` 语义，不新增第二个键，也不在 Playground 单独维护
一套键盘循环。

在 SDK 的统一交互分发处按以下顺序处理：

```text
收到 interactPressed
  ├─ 驾驶中且当前载具 condition=flipped/stuck
  │    └─ 尝试 recoverVehicle()，成功或失败都消费本次 F
  │
  ├─ 徒步且最近交互载具 condition=flipped/stuck
  │    └─ 尝试 recoverVehicle(targetId)，成功或失败都消费本次 F
  │
  ├─ 驾驶中且没有回正/脱困候选
  │    └─ 执行原有下车、着陆或飞行交互
  │
  └─ 徒步且没有回正/脱困候选
       └─ 执行原有场景交互或上车逻辑
```

需要保持以下输入约束：

- 只响应按键边沿，不因长按连续回正或连续上下车；
- 载具回正成功后仍保持当前控制权，下一次 F 才执行下车；
- 徒步回正成功后不自动获得载具控制权，下一次 F 才执行上车；
- `humanoid.setInput`、Episode 输入和调试命令仍遵守各自的输入所有权；
- 正常飞行中的飞机/飞龙继续走现有着陆、取消着陆或退出逻辑；只有飞机持续有操控
  意图却完全不动、达到阻挡窗口时，才从 `airborne` 转为 `stuck` 并开放脱困。

## 对外观察与 Playground

在 `HumanoidSnapshot.vehicleDynamics` 和 `inspectVehicles()` 中暴露统一结果：

```ts
{
  condition: 'normal' | 'flipped' | 'stuck' | 'airborne' | 'not-applicable',
  recoveryReason: 'flipped' | 'blocked' | 'flipped-and-blocked' | null,
  recoveryAvailable: boolean,
  ...
}
```

Playground 不自行计算姿态和卡住时间，只读取 SDK 状态并显示动态提示：

- 正常载具附近：`F 上车`；
- 翻车或卡住载具附近：`F 回正 / 脱困`；
- 驾驶正常载具：`F 下车`；
- 驾驶翻车或卡住载具：`F 回正 / 脱困`；
- 空中飞行载具：继续显示原有飞行提示；
- 状态是翻车/卡住但暂时无法执行：显示失败原因，不显示可执行的回正提示。

现有 Playground 的“原地扶正”按钮可以继续保留，但按钮状态和文案应基于
`recoveryAvailable`，不再只根据车型显示。历史上显示 `R` 的文案应改为 F 语义
或改成无快捷键的按钮说明，避免与实际默认绑定不一致。

## 预计改动边界

### Three SDK

- 新增统一车辆状态/回正候选判定模块；
- 扩展 `VehicleState` 或其派生诊断状态；
- 扩展 `HumanoidActor.recoverVehicle()` 的目标选择和徒步调用；
- 在 `HumanoidRuntime.advanceOwned()` 的 F 交互分发处增加回正/脱困优先级；
- 扩展 snapshot、inspection 和相关公共类型。

### SDK Playground

- 读取 SDK 的状态字段更新底部交互提示；
- 更新回正按钮的显示条件和文案；
- 删除或修正旧的 R 快捷键暗示；
- 不增加 Playground 自己的物理判断、计时器或第二套输入所有权。

### 文档与生产消费者

- 更新 Three SDK 载具交互契约和能力说明；
- 检查 Creator 的命令描述是否需要增加 `recoveryReason`/状态说明；
- 检查 Episode 的输入回放是否保持 F 的边沿语义；
- 保持 `vehicle.recover` 命令可用，并与按键路径使用同一执行实现。

## 验证计划

### 状态判定

- 正常停放的汽车为 `normal`；
- 汽车 90°、180°、270° 侧翻/倒扣为 `flipped`；
- 飞机在正常空中飞行/翻滚为 `airborne`，不提供地面回正；若持续操控却完全不动，
  则识别为 `stuck`，用于处理穿透建筑或碰撞代理失配；
- 飞机落地后侧翻或倒扣为 `flipped`；
- 汽车从坡面起跳的短暂离地阶段不为 `flipped`；
- 正常停车、主动刹车、无输入状态不为 `stuck`；
- 持续驾驶输入且被建筑阻挡，超过稳定时间窗口后为 `stuck`。

### F 键行为

- 徒步靠近正常载具：F 上车；
- 徒步靠近翻车载具：第一次 F 回正，第二次 F 上车；
- 徒步靠近卡住载具：第一次 F 脱困，第二次 F 上车；
- 驾驶正常载具：F 下车；
- 驾驶翻车或卡住载具：第一次 F 回正/脱困，第二次 F 下车；
- 回正失败不触发上下车；
- 长按 F 不重复执行动作；
- 飞行中 F 仍遵守原有着陆/退出行为。

### 状态一致性

- HUD、`snapshot()`、`inspectVehicles()` 返回同一状态；
- 回正后速度、角速度、轮胎/刚体状态和视觉采样一致；
- 回正不改变驾驶关系和相机模式；
- 徒步回正不移动人物；
- Creator 命令和 Episode 回放不创建第二个物理或输入循环。

## 实施顺序

1. 先实现并测试状态判定，包括落地飞机和卡住检测；
2. 抽取/复用现有安全回正逻辑，支持指定附近载具；
3. 接入 SDK 内部 F 分发优先级；
4. 扩展 snapshot、inspection 和 Playground 提示；
5. 更新 SDK/Creator/Episode 文档与公共契约；
6. 完成运行时测试、Playground 构建和实际交互回归。
