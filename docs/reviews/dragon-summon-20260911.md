## 当前玩法

训练场以地面人物开场，所选龙在空中等待。H 召唤当前龙，安全落点优先位于人物侧前方；龙从实际当前位置飞来，不传送人物或自动登乘。落稳后走到鞍侧 F 上龙，Space 起飞，空中 F 着陆，落稳后 F 下龙。步行时切换龙型号保留人物位置；原来的 F、Space、T 和驾驶映射继续使用。

H 属于公共 `summonDragon` 输入绑定，可重映射。固定步输入为 `humanoid.actions.summonDragon`，SDK 方法为 `world.humanoid.summonDragon(instanceId?)`；Playground 的 `summon_dragon` 工具调用同一方法。人物必须未骑乘、未忙于其他动作，并站在干燥地面。

每个飞龙实例保存 `summon.phase`（flying/landing/arrived/blocked）、固定目标、航点、计时和原因。八个落点方向及三个巡航高度候选经过地面、核心体积和飞行通道检查；速度受加速度和制动距离约束，朝向与侧倾有速率限制。真实运动仍在原 SDK 控制器中做连续体积扫掠并驱动飞行动画。接近后复用已实现的下降、收翼和地面状态，不增加时钟、物理世界或相机拥有者。

人物走开不会拖着已选落点移动。途中新增障碍会停止接近并报告受阻，可以换位置再次召唤；未提供任意复杂地形的全局寻路。停驻的龙可再次被召唤，先起飞再飞向新落点。快照与显示插值深拷贝路线，外部修改快照不会改写导航。

## 下龙不能移动的调查与处理

首次在用户 D07 页面上观察到：人物能力显示可移动，但两秒前进输入没有位移。后来开发热更新重置了现场，因此没有保留足以将该截图唯一归因于某一个碰撞体或输入状态的诊断，不声称完整复原了原故障。

源码确认调试面板的单步曾调用 `runtime.setInput(emptyInput())`，未释放持续输入覆盖；现在改为 `sdk.step({humanoid:emptyInput()},1)`，并清理 UI 输入。这个缺陷能使正常键盘被零输入覆盖，但不能仅凭截图断言用户触发过单步。

下龙落点从单点胶囊净空检查扩展为：还必须能向鞍外迈出 0.8 米，且有真实地面支撑和连续通道；两侧都不满足时保留骑乘并说明原因。没有关闭人物或环境碰撞。检查界面同时暴露已有 `inspectControls()` 的实际输入来源，方便区分输入占用与几何阻挡。
