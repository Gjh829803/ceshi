# 相机系统交接审计

审计起点为相机分支 `3533125c`，历史对照为旧架构 `28524686`。
起因是连续出现骑马抖动、贴墙环绕人物偏离，用户要求主动检查同类问题。
本轮检查输入准备、固定提交、显示插值、视角激活与切换、主体搬迁、上下坐骑、
重置、删除目标、Creator 捕获及 Episode 录制消费者。

## 责任归属

不能将近期问题统一归为旧逻辑缺陷，也不能以架构方向正确代替迁移行为验证。

| 问题 | 历史对照与归属 |
| --- | --- |
| 骑马零深度接触停顿 | 旧内核已有零移动分离缺陷，但旧上层采用默认 .02 米支点间隙；`e5c6edd5` 迁移脚本固定写 0，并扩展查询路径。本次迁移改变了触发条件，验证未覆盖该组合。 |
| TOI=0、扫掠起点及最终眼球检查 | 旧内核已有缺口；重构增加了使用同一求解器的路径，包括旧 tuned 第一人称原先未执行的碰撞。 |
| 碰撞后机位与朝向不同步 | 旧 preserve-opening 路径已有缺口；旧 tuned 人物、肩位、车辆会重新 lookAt，重构的共享 position-only 约束漏掉了这些已有补偿。属于旧缺口与新增遗漏并存。 |
| 插值时不同臂长造成构图漂移 | 旧路径也存在直接位置/朝向插值的数学缺口，部分路径仅在再次发生空间修正时补偿，未形成完整构图约束。 |
| 提交后还读取准备阶段方向缓存 | `cameraBasis` 由 `27a10429` 引入，旧架构没有此缓存生命周期；明确属于本次新增回归。 |
| 显示座位/备用眼位、同视角激活入口 | 新共享主体适配器和显式视角 API 的状态交接遗漏。 |
| 垂直视线转为世界北方输入 | 旧 authored 分支已有固定方向回退；新统一 quaternion 路径将其扩展到 follow 消费，未针对垂直视线补齐规则。 |

独立历史内核探针复制旧版本计算模块至忽略目录运行：同一零深度请求，旧默认
.02 正常跟随，旧显式 0 停在旧眼位，修复版两者均正常；TOI=0 且未标 overlap
时，旧版两种间隙均错误收缩至支点，修复版均正常。没有用旧完整 runtime 重演
同一沙海 case，因此不声称旧版必然出现完全相同的停顿次数或画面。

## 本轮确认并修复

| 缺陷 | 可复现证据 | 修复与防回归 |
| --- | --- | --- |
| 准备方向缓存越过提交边界 | subject-up 人物侧移一步后实际镜头朝 +X，后置消费者仍读 −Z，差 90° | 固定提交后、afterUpdates 前清除缓存；测试后置回调、外部读取与暂停后方向。 |
| 同视角显式激活跳位 | 等待期间主体下降 1 米，鼠标/移动激活不跳，显式选当前视角却令相机下降 1 米 | 共用 pending activation；测试零/非零过渡、切走切回、重置。未选中旧视角越界不能阻挡合法第一人称。 |
| 显示锚点混用两个采样时刻 | 车辆 x=0→10 时，座位视角 alpha=0/.5/1 全部使用固定帧眼位；真实运动世界回归也观察到 .083333 米误差 | seat 和备用 eye 使用同一车辆显示位置/旋转；测试车辆直接绑定、骑乘人物绑定及肩位/第一人称。 |
| 垂直视线输入转北 | yaw=1.1 时接近垂直，原输入突然变为世界 −Z | 只有数值退化时由镜头右轴派生水平前向；测试接近和精确垂直方向。 |

规则只维护在[相机所有权与交接](../three-sdk-architecture.md#相机控制权与交接)。
没有改资产预设、场景参数、车辆物理或生产流程，没有新增生产门禁。

- 原始轨道基底、相对构图、参考方向在策略、插值和生命周期搬迁中的传播完整。

## 验证边界

上述检查覆盖已列出的交接和数值回归，不能替代任意地图的完整手感验收。
镜头位于极窄空间时仍会拉近，根节点入镜不等于人物全身完整可见；本轮未添加
近距离人物淡出或新视角算法。精确反向视线与极点策略继续遵守权威架构中的取舍。
