# Three 分支审查协议

以 [Three SDK 架构](../three-sdk-architecture.md) 和
[生产边界](../three-sdk-data-production.md) 审查当前分支。实际源码、接口消费者和对应验证证据决定结论。

## 模式与前置

| 模式 | 对象 | 必查维度 |
| --- | --- | --- |
| A 设计审查 | 设计文档与对应消费者 | D1、D2、D3、D6 |
| B 变更审查 | 指定 base/head 的 diff | D2、D3、D4、D5、D6；职责变化时加 D1 |
| C 整仓审计 | 明确范围的当前源码 | D1–D6 |

先记录分支、SHA、基线与工作区改动，依次阅读 AGENTS.md、本分支架构、生产说明和
受影响组件文档。涉及运行时行为时使用 [专项检查表](runtime-deep-review-checklist.md)。
审查默认只读，不改源码、金标、冻结输入、任务身份或审核记录；修复另按授权执行。
外部任务、未知请求重试和发布操作遵循当前任务授权。

## D1 职责与范围

- 作者自由绘制 Mesh，推荐复用提供的人形；自制主体绑定明确的碰撞、运动与动画能力。
- SDK 负责统一物理、运动、动画、相机和生命周期；作品可修改 SDK 源码并重新构建。
- Creator Host 负责浏览器工具与 v0.2 自检交付；Episode 独立消费世界并生产素材。
- UI、模型输入和输出分层；云调度、自然语言理解、视频服务和审核不进入 SDK 核心。
- 不增加重复场景语言或无实际消费者的通用框架。每个模块都应有明确的当前消费者。
- 缺失能力与已实现能力的缺陷分别报告；自动交付订阅、视频提交和最终视频验收仍未接通。

## D2 公开接口与 Agent 用法

- 公共类型以 `packages/three-world/src/contracts.ts` 为准；schema、工具、README、
  示例和实际运行消费者必须一致，不维护另一套独立 API 草案。
- 数值的单位与坐标域必须清楚；判别联合表达互斥状态，命令参数与实体身份可检查。
- 注册内容决定实际可用能力；不以一个动画名称或速度回调承诺完整运动/寻路能力。
- 区分命令接受与操作完成、Creator operation 与 World operation。失败具有可定位
  的诊断，不允许用成功标签掩盖未执行或被拒绝的行为。

## D3 声明与事实

- README、分支说明、工具结果和报告的每个能力声明都能定位到实际消费者。
- Creator 的技术交付与视觉/玩法评价独立；真实自检必须覆盖当前源码、运行时和输入计划。
- Episode 的锚点通过、Prompt 完成、素材就绪、请求准备和最终视频完成分别表达。
- 固定案例、旧 runtimeHash 与部署记录保持原义，不能替代当前源树的部署验证。

## D4 状态与数据一致性

- 一个物理世界、一个模拟时钟和明确的写入权；视觉展示不反向决定物理状态。
- reset、pause、Episode 初始化和异步完成不泄漏旧按键、运动、相机或任务状态。
- 世界源码、实际运行时、输入计划、录制 trace 和视觉事件各自有正确身份与消费者。
- 恢复保留确切 request/job；未知提交先协调原请求。成功片段不得被失败案例无故重做。
- 人工反馈沿用现有共享身份；旧图片决定不自动批准新生成图片。

## D5 可维护性与失败路径

- 复用 Three/Rapier 与已存在的 SDK 接口；扩展必须有明确职责和真实调用方。
- 核对直接依赖、资源生命周期、取消、部分失败与重试；不以兼容旁路制造第二权威。
- 测试覆盖实际失败和边界转换，避免只检查对称稳态或复制实现。
- 验证安装依赖的实际语义，不用过期引擎经验代替源码证据。
- 私有配置、凭据、案例媒体、provider journals 和审核数据不进入 Git 或模型工作区。

## D6 验证与结论范围

标记 `static-read`、`automated-contract`、`rendered-visual`、`manual-interaction`
证据层。每条执行命令记录 exit code；环境失败、产品失败、未执行分别报告。

按 [Runtime 检查表](runtime-deep-review-checklist.md) 选择受影响验证。纯文档检查
链接、声明和 diff；工具会读取的文档增加直接消费者检查。Three 范围测试不称为整仓
CI；已通过的宽验证包含窄验证时不重复执行。构建、浏览器、视觉、人工交互与真实云端
验收不能互相替代。后续修改只使其可能影响的证据失效。

## 输出格式

先列可复现、可行动的 findings；无发现时写明，并保留未验证范围。

每条 finding 包含：优先级与标题、当前源码路径/行号、触发条件、预期与实际行为、
影响、建议和复验方式。发现必须在当前源码上复现。

最后列 D1–D6 覆盖、执行命令/结果、未运行项和结论。`GO` 仅适用于声明的审查范围，
不授权合并或部署；未解决的 P0/P1、必需验证失败或关键证据缺失报告 `NO-GO`。
只有明确要求保存报告时才新增带日期文档，否则在审查回复中交付。
