## 阻塞项

各字段分别合法不代表最终镜头合法：基础 FOV 170° 加启用的速度偏移 20°，
可以安装，却在满速固定步生成 190° 并抛出 CAMERA_PROPOSAL_INVALID。
同时，热编辑会保留旧速度效果历史；新配置 170° + 5° 本身合法，但旧 20°
效果仍可能造成越界。

修复在现有配置解析关系检查中校验启用效果的完整范围，必须严格小于 180°。
校验发生在预设与主体覆盖合成之后；preserve-opening 使用真正的 opening FOV，
隐式开场在采用实际作者镜头后完成检查，不使用 inactive preset FOV 代替。
安装失败保持原配置、镜头和提交状态。热编辑仅将保留的速度 FOV 偏移约束到
新配置的启用范围，保留轨道与其他平滑历史；关闭效果时清除其历史偏移。

新增 8 项参数化/运行时回归先失败，再通过：三种视角的 180° 边界、禁用效果、
合法近边界值、预设与主体叠加、显式/隐式开场、非法安装原子性、真实运动满速、
缩小效果范围的热编辑、编辑会话禁用与撤销均得到覆盖。
规则与派生产物维护仍在 [SDK 配置说明](../../packages/three-world/src/config/README.md)，
没有增加单独生产流程或降低运行时 proposal 检查。

## CI 超时

旧 head 的 Actions run 34795409990 第 2 次运行：最初的依赖扫描已过，后续
Episode MCP 8 项测试中 4 项超时；本地原样复现 4 失败 / 4 通过，耗时 136.80 秒。

原因是测试动态生成的 main.ts 仍调用已删除的 setCameraFollow({targetEntityId})。
浏览器中场景启动失败，工具持续等待就绪而表现为 5 秒/60 秒超时。改为安装
CameraDocument 并保留作者开场后，原断言与超时不变，8/8 通过，总耗时 22.24 秒；
两条真实 stdio/Chromium 路径分别约 6.05 / 5.58 秒。当前包、应用与脚本扫描中，
剩余直接旧调用只属于显式迁移器测试输入。

## 后续全仓库依赖扫描超时

Actions run 34797329036 基于 `7700518e`，契约测试 572/573 通过；唯一失败为
repository-layout 的全仓库扫描耗时 6504 ms，超过默认 5000 ms。该运行在契约
阶段退出，尚未执行后续 Episode 测试，不能据此判断 MCP 修复失败。

扫描器原先对每个源码文件创建完整 TypeScript AST，包括约 1.15 MB 的相机生成
校验器。现先做保守文本预筛选：只有不包含目标 scope、且不含可能构造 scope 的

package.json 身份与所有依赖 scope 检查保持不变。转义斜杠无法构造不含斜杠的
scope 名称，其余转义均进入 AST，避免漏掉 Unicode、hex、identity escape 或续行。

新增回归覆盖静态/动态导入、export、import-equals、import type、require.resolve、
模板字面量、转义引用与生成文件；已有注释/负例字符串测试保持通过。未调整默认
超时，未排除文件或缩小依赖检查范围。
