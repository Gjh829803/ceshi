# 世界生命周期维护边界

## 目标与当前范围

基于 dev `422230e3`，先提取既有世界运行状态与浏览器帧调度，保持现有效果。
生命周期不是新的物理、动画或相机算法，也不创建第二个模拟时钟。
本阶段不新增公共组件基类、自动依赖排序、资源缓存或资产库 API。

## 运行规则

`WorldLifecycle` 是每个 `WorldEngine` 的内部成员，不是全局单例或公共插件注册器。
状态只有 `stopped / running / disposed`；异步准备仍由原 `ThreeWorld` 层负责，
不在两层分别复制一套“准备完成”状态。此阶段尚不是完整的实体/组件生命周期体系。

- `start`：检查未销毁、避免重复启动、封存初始状态、开启输入，再调度首帧。
- 首帧时间差保持原实现为零。恢复运行不会把暂停时长当成模拟欠账。
- 每个帧回调都检查所属代际；已取消或被重启替换的回调不能推进世界或续订循环。
- `stop`：关闭实时循环、清空输入及时间累积并取消待执行帧；停用后仍允许现有手动 `step` 和 `render`。
- `beginDisposal`：先停止，再标记销毁；各系统随后按原顺序释放，不重复执行。
- Node 没有 `requestAnimationFrame` 时，仍允许 `start` 后显式推进。
- `reset` 仍是现有的恢复操作，不通过销毁重建世界来替代。

帧内顺序保持为：

```text
浏览器帧时间差
  → 原 advance / fixedStep（零次或多次）
      → 更新回调 → 相机输入准备 → 人物/物理推进
      → 动画更新 → 相机状态提交 → 更新后回调
  → 原 render / withPresentation（显示采样、还原）
  → 原性能诊断回调
  → 若当前代际仍运行，登记下一帧
```

## 第二步：任务作用域登记与取消

`WorldTaskScopes` 仅持有本世界活动任务的 AbortController 集合，提供登记、
任务结束移除、同步取消和清空登记。它不持有世界状态、资源、相机或物理引用，
也不复制 epoch、实体 generation、启动 generation 或 Episode 时钟归属。

- `runTask` 在原位置登记，并在原 `finally` 位置移除；临时资产释放逻辑不变。
- `stop` 不取消普通任务。暂停后合法的后台任务仍可完成。
- 重置与地图替换仍先使世界代际失效，再在原位置取消并清空登记。
- 销毁仍在标记世界失效后取消，登记保留到各任务结束；不把销毁改成重置。
- 同步 abort 监听器仍按原 Set 迭代规则执行，不改为快照遍历或先清空后通知。

[任务作用域回归测试](../packages/three-world/src/world-task-scopes.test.ts) 包含五组
17 项现有行为基准：暂停、重置、销毁与迟到模型、同世界任务隔离、成功/失败地图替换。
模型资源用本地真实 GLB 字节和实际加载器验证，控制加载时机及任务等待，
观察实例、骨架、材质与共享几何释放；这不是 GPU 显存或长期泄漏压力测试。

## 销毁异常收尾

世界和引擎继续使用各自的 `dispose`，不引入新的公共清理框架。
正常调用顺序、资源归属、既有回调的错误记录方式保持不变。

- 引擎进入销毁态后的独立资源释放，以及世界的展示层、阴影恢复、引擎和资产库释放，逐项尝试；一项失败不会跳过后续独立所有者。
- 原先会直接向调用者抛出的错误，改在上述收尾结束后抛出首个原始值，同时记录诊断。包括 `undefined`、`null` 等异常值，不用真假判断决定是否抛出。
- 原先仅记录的角色、资产、用户回调及世界自有资源异常，仍按原方式记录，不把它们改成新的对外异常。
- 重复 `dispose` 不重试已经执行的步骤；不能因此保证抛错所有者内部的每个资源都已释放。
- 世界在调用借用渲染器前标记失效，防止恢复录制视口时同步重入导致回调执行两遍。Episode 相机租约和视口恢复也逐项收尾；恢复失败仍释放引擎和资产，最后抛出首错。
- 此边界不覆盖进入引擎销毁态前的停止操作，没有改动排队命令撤销或任务取消规则。

[销毁回归测试](../packages/three-world/src/world-disposal.test.ts) 验证正常顺序、
自有/借用渲染器、真实 GLB 的退役/重置与共享资源、异常后的独立收尾、多个异常的首错保留，
以及重复退出。[Episode 回归测试](../packages/three-world/src/episode.test.ts) 另行覆盖普通及原生人物世界的视口恢复异常、借用渲染器同步重入。渲染器归属用 GPU 边界替身检查；实际 DOM/流由既有 Presentation 浏览器回归覆盖。
