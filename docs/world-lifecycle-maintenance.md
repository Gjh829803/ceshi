# 世界生命周期维护边界

## 目标与当前范围

基于 dev `422230e3`，先提取既有世界运行状态与浏览器帧调度，保持现有效果。
生命周期不是新的物理、动画或相机算法，也不创建第二个模拟时钟。
本阶段不新增公共组件基类、自动依赖排序、资源缓存或资产库 API。

## 运行规则

`WorldLifecycle` 是每个 `WorldEngine` 的内部成员，不是全局单例或公共插件注册器。
状态只有 `stopped / running / disposed`；异步准备仍由原 `ThreeWorld` 层负责，
不在两层分别复制一套“准备完成”状态。此阶段尚不是完整的实体/组件生命周期体系。

- `start`：检查未销毁、避免重复启动、封存初始状态、开启输入，再调度首帧。
- 首帧时间差保持原实现为零。恢复运行不会把暂停时长当成模拟欠账。
- 每个帧回调都检查所属代际；已取消或被重启替换的回调不能推进世界或续订循环。
- `stop`：关闭实时循环、清空输入及时间累积并取消待执行帧；停用后仍允许现有手动 `step` 和 `render`。
- `beginDisposal`：先标记销毁以阻止外部输入释放回调重入，再执行原停止步骤；各系统随后按原顺序释放。停止失败也继续独立收尾。
- Node 没有 `requestAnimationFrame` 时，仍允许 `start` 后显式推进。
- `reset` 仍是现有的恢复操作，不通过销毁重建世界来替代。

帧内顺序保持为：

```text
浏览器帧时间差
  → 原 advance / fixedStep（零次或多次）
      → 更新回调 → 相机输入准备 → 人物/物理推进
      → 动画更新 → 相机状态提交 → 更新后回调
  → 原 render / withPresentation（显示采样、还原）
  → 原性能诊断回调
  → 若当前代际仍运行，登记下一帧
```

## 第二步：任务作用域登记与取消

`WorldTaskScopes` 仅持有本世界活动任务的 AbortController 集合，提供登记、
任务结束移除、同步取消和清空登记。它不持有世界状态、资源、相机或物理引用，
也不复制 epoch、实体 generation、启动 generation 或 Episode 时钟归属。

- `runTask` 在原位置登记，并在原 `finally` 位置移除；临时资产释放逻辑不变。
- `stop` 不取消普通任务。暂停后合法的后台任务仍可完成。
- 重置与地图替换仍先使世界代际失效，再在原位置取消并清空登记。
- 销毁仍在标记世界失效后取消，登记保留到各任务结束；不把销毁改成重置。
- 同步 abort 监听器仍按原 Set 迭代规则执行，不改为快照遍历或先清空后通知。

[任务作用域回归测试](../packages/three-world/src/world-task-scopes.test.ts) 包含五组
17 项现有行为基准：暂停、重置、销毁与迟到模型、同世界任务隔离、成功/失败地图替换。
模型资源用本地真实 GLB 字节和实际加载器验证，控制加载时机及任务等待，
观察实例、骨架、材质与共享几何释放；这不是 GPU 显存或长期泄漏压力测试。

## 销毁异常收尾

世界和引擎继续使用各自的 `dispose`，不引入新的公共清理框架。
正常调用顺序、资源归属、既有回调的错误记录方式保持不变。

- 引擎进入销毁态后的独立资源释放，以及世界的展示层、阴影恢复、引擎和资产库释放，逐项尝试；一项失败不会跳过后续独立所有者。
- 原先会直接向调用者抛出的错误，改在上述收尾结束后抛出首个原始值，同时记录诊断。包括 `undefined`、`null` 等异常值，不用真假判断决定是否抛出。
- 原先仅记录的角色、资产、用户回调及世界自有资源异常，仍按原方式记录，不把它们改成新的对外异常。
- 重复 `dispose` 不重试已经执行的步骤；不能因此保证抛错所有者内部的每个资源都已释放。
- 世界在调用借用渲染器前标记失效，防止恢复录制视口时同步重入导致回调执行两遍。Episode 相机租约和视口恢复也逐项收尾；恢复失败仍释放引擎和资产，最后抛出首错。
- 停止时即使宿主 DOM 释放鼠标锁定失败，也清空按键/待消费输入、关闭键盘、归零时间累积并取消帧代际。输入卸载仍解除监听、恢复样式和撤销登记；错误保留。引擎销毁将这一入口失败纳入独立收尾。
- 没有改动排队命令撤销或任务取消规则；不保证失败的宿主 API 已真正解除浏览器锁定。

[销毁回归测试](../packages/three-world/src/world-disposal.test.ts) 验证正常顺序、
自有/借用渲染器、真实 GLB 的退役/重置与共享资源、异常后的独立收尾、多个异常的首错保留，
以及重复退出。[Episode 回归测试](../packages/three-world/src/episode.test.ts) 另行覆盖普通及原生人物世界的视口恢复异常、借用渲染器同步重入。渲染器归属用 GPU 边界替身检查；实际 DOM/流由既有 Presentation 浏览器回归覆盖。

## 模块接入：复用现有回调

当前核心需求使用现有构造函数/工厂和回调即可，不另建 `Awake/Start/OnEnable` 公共组件体系。
这不是统一组件事件 API：模块初始化和启停仍由其现有所有者显式调用，世界控制唯一时钟与最终释放。

| 阶段 | 实际执行边界 |
| --- | --- |
| 初始化 | 世界 `create` 和模块构造/工厂；初始资源准备仍在 `initialise/start`。已存在的异步取消归 `WorldTaskScopes` 与原代际检查 |
| 就绪 | `await world.start()` 完成资源/编译准备和首帧；不新增独立 ready 调度 |
| 模块启用/停用 | 使用模块已有开关，如碰撞显示的 `setEnabled`；没有开关的附加行为可使用既有订阅/取消订阅。世界暂停不等于全部模块停用 |
| 更新 | 模拟行为 `onUpdate`；展示 `onRender`；观测 `onRuntimeSample`。都使用现有时钟；暂停后显式 step 仍触发 update |
| 重置 | 保留同一模块与订阅，复用 `onReset`；不销毁重建世界 |
| 卸载/销毁 | 模块可主动取消订阅并释放自有资源，世界 `onDispose` 做最终清理；调用原模块 dispose，不接管其业务算法 |

相机仍是引擎所拥有的现有模块，更新位置和输入/物理/动画顺序不变；相机自己的目标绑定和控制权生命周期不与世界运行状态混为一谈。
实体仍通过注册/撤销、基线恢复和原资产所有权释放；不增设第二份实体状态或未来资产库缓存。

回调登记只允许在世界/引擎存活时发生，销毁期间及之后新登记抛 `WORLD_DISPOSED`。
已经取得的取消订阅函数在销毁后仍可重复调用。世界销毁后清空更新、重置、销毁的回调引用；
保留原 Set 的活跃迭代和取消订阅行为，不改变正常调用顺序、重置语义或旧回调错误策略。

[销毁回归测试](../packages/three-world/src/world-disposal.test.ts) 使用真实 `ObjectColorBinding` 验证
初始化→更新→重置→取消更新→世界销毁时恢复原材质及只释放一次，并验证销毁回调抛错和重入登记边界。
既有碰撞显示/调试模块继续使用自己的启停与释放逻辑；本步不迁移这些模块或引入包装类。

### 本轮确认并修正的底层缺口

世界/引擎已有“独立资源继续释放、最后报告首错”的规则，但原生运行时、Simulation、
人物控制器和环境查询内部仍有串联 `dispose`：一个清理抛错会跳过后面的独立所有者。
真实运行时故障注入已在修复前复现四种中断：模拟、单个人物、交互、人物动作清理失败。
这属于异常路径缺口，不能据此声称用户正常游玩已经发生了这些异常。

新增内部 `disposeInOrder` 只做按既定顺序尝试独立收尾并保留首个异常值；不持有资源、
调度器或世界状态，不自动排序。各模块仍列出自己拥有的资源，正常释放次序不变。
环境查询增加正在销毁保护，完成后（包括失败时）进入已销毁态，防止递归/重复释放。
未知的第三方清理如果自身只完成一半，不能保证它内部全部资源均释放；这里保证的是
不阻断其他独立所有者，并让失败继续传递到现有世界诊断。

本轮不改固定步、输入响应、物理家族算法、相机算法，也不新增测试页面功能。
整体生命周期重构尚未宣称完成：下一步是实体生命周期协调边界，而不是扩展模型试玩页。


## 2026-09-17 实体生命周期协调提取

本轮延续项目公共 SDK 主线，不修改 Playground 页面、不新增资产或公共功能。

```text
ThreeWorld：命令校验、任务/捕获目标/公共元数据协调
  → setEntityActivation / removeEntity：明确启停、移除与永久销毁的提交边界
WorldEngine：执行顺序、物理/输入/动画/相机的原有调用
  → EngineEntityLifecycle：唯一运行实体登记、启停标记、重置基准、退役记录
  → 各系统：执行自己的绑定、运行与清理
```

[EngineEntityLifecycle](../packages/three-world/src/entity-lifecycle.ts) 是内部实现，未导出公共 API。
它持有原 Engine 的 Map/Set，Engine 通过只读视图查询，不复制另一份身份或生命周期状态。
ThreeWorld 的公共元数据/命令代际仍由 ThreeWorld 持有，与引擎的物理/显示绑定有不同职责；
本轮不把两者错误合并成同一结构，也不增加状态镜像。

- **登记**：原验证及物理/人物绑定成功后，在原提交点登记同一个对象。失败回退仍由既有绑定所有者执行。
- **启停**：乘骑关联由原生所有者给出；内部实体管理计算祖先与局部停用的有效状态，
  在原来的逐实体位置调用物理开关与输入清空。世界暂停与实体停用仍不同。
- **移除/退役**：物理解绑、场景脱离、动作取消、退役顺序保持；临时实体与基准实体使用原有资源策略。
- **永久销毁**：同一实例的基准与停用记录一起解除，输入初始主体和相机目标仍由各自所有者处理。
  公共操作仍在清理前标记已提交，因此清理错误不会假装实体尚未被删除。
- **重置**：在原物理解绑与物理重绑之间恢复实体归属、父子关系、矩阵、可见性和启停基准。
  固定时钟、人物/载具重置、相机重置及通知的先后顺序留在原 Engine 中。
- **世界销毁**：各系统清理完，在原位置清空运行记录、退役集合和基准。

这一步收敛的是实体生命周期的记录所有权与调用边界，不是将物理、动画、人物、相机改成一个通用大系统。
验证复用原来的公共行为测试，不删除断言、不改测试预期来适配提取结果。


## 2026-09-17 真实项目调用链验收

沿 Playground 的主页面 `main.ts`、Creator 的公共 observer 桥接以及 SDK Episode 端口核对，
这些入口继续调用同一个 ThreeWorld/WorldEngine；隔离资产页不是新的运行时。

| 操作 | 现有执行边界 | 本轮证据 |
| --- | --- | --- |
| 启动 | ThreeWorld.initialise → prepareRendering → 首帧 → Engine.start | 并发启动、首帧失败、编译失败重试与晚到编译测试 |
| 暂停/恢复 | ThreeWorld.stop/start → WorldLifecycle；固定步留在 Engine | 综合训练场连续三次暂停恢复；暂停时间不进入模拟 |
| 重置 | 世界取消旧任务 → 公共基准 → Engine 实体/物理/相机重置 → 回调 | 公共集成、实体与 Episode 回归；真实页面重置 |
| 切场景 | Playground session.switchMap → native switchMap → simulationReplaced | 园区/赛车场往返；成功切图取消旧任务、失败切图保持现态测试 |
| 销毁 | 页面 pagehide → session.dispose → ThreeWorld/Engine → 各资源所有者 | 真实页面退出后待执行帧为 0，公共 observer 解除；销毁故障注入回归 |
| 异步晚到结果 | 世界 epoch、任务 signal 和原生 lifecycleGeneration | 迟到加载、销毁、重置、换图回归；不新增身份来源 |

本轮确认并修正两项共享 SDK 异常路径：

1. `runTask` 的 finally 原先在第一个临时资产释放异常后停止遍历，留下其余资产，
   还会覆盖原任务异常。现在结束任务登记后尝试每个临时资产的释放；任务失败/过期时
   保留原任务错误，并记录清理错误。任务本来成功、但清理失败时报告首个清理错误。
   已交给实体的资产和其他任务/调用方资产不受影响。
2. 原始模型和 WorldAssets 的清理用 `??=`/真假判断保存异常，会吞掉 null/undefined，
   也可能让后续错误替换首错。两处复用已有 disposeInOrder，保留正常释放顺序，
   所有独立清理继续执行，最后报告首个原始异常值。

新增五项故障回归在修复前均失败，修复后通过；既有断言未删除或放宽。
900 帧原始数值基准完全一致，覆盖 30/60/144 Hz、暂停恢复、重置及延迟帧。
真实综合训练场验证步行、三视角、暂停恢复、驾驶/倒车、重置、换图往返与退出，无页面错误。

上述验收是所列路径的确定性对照及真实浏览器流程，不是全仓测试、全资产全地图测试，
也不是 GPU 显存、长期运行泄漏或性能压力证明。清理继续执行不保证第三方抛错函数内部
未完成的资源能被补救；异常仍如实报告。当前改动仍在独立本地分支，尚未提交或合入 dev。


## 2026-09-17 创建失败的所有者回收

共享 SDK 的两层工厂现在也遵循已有异常收尾规则：

- `WorldEngine.create` 在构造失败后按原顺序尝试释放已创建的导航和物理所有者，导航释放失败不再跳过物理。
- `ThreeWorld.create` 已得到完整世界对象时由该世界执行销毁，覆盖资产管理器；尚未得到完整世界对象时，只释放工厂已取得的引擎和资产管理器。
- 创建 Promise 保留最初异常（包括 null/undefined）；收尾异常通过 `WORLD_CREATE_CLEANUP_FAILED` 警告报告，不替换创建错误。
- 成功创建与固定步路径没有重新排序，借用渲染器仍不由世界销毁。

`world-disposal.test.ts` 新增五项故障注入，在修复前分别复现导航错误掩盖创建错误、引擎错误掩盖目录错误，以及后期设置失败漏掉资产管理器收尾。此处覆盖的是工厂取得所有权后的失败回收，并不声称已覆盖每个第三方构造函数内部的部分分配。

相关九个测试文件共 277 项通过；900 帧已有基准精确一致。类型、lint、测试归属清单及 Creator SDK 运行时构建通过。本轮未运行全仓完整门禁或长期泄漏压力测试。

### 换图和重置的异常交接

- 准备完成、旧所有者开始退役：继续接管新环境/模拟，完成通知、输入清空和显示同步，再报告清理错误。

## 2026-09-18 可选实体回调注册接口

共享 SDK 新增 `world.registerEntityLifecycle(entityId, callbacks)`，并通过公共
`EntityLifecycleCallbacks` 类型及 Creator 的 getting-started / programming /
nonhuman-subject / assets / extensions 主题发现。接口绑定已经登记的具体实例；
资产库以后完成后，仍先加载、加入世界，再注册该实例的行为。

- 可选同步回调：`onInit / onEnable / onDisable / onUpdate / onReset / onDispose`。
- `entity-callbacks.ts` 只保存订阅、实例引用和最后通知过的启用状态；实体是否存在、
  有效启用及重置归属仍从现有世界与引擎读取，不复制实体管理器。
- `onUpdate` 接在原 `ThreeWorld.beforeTick` 中已有世界更新订阅之后，使用同一个固定步。
  世界暂停不等于实体停用；只读检查、渲染不产生新的更新。
- 父子与乘骑组合继续使用现有启停策略。`entity.despawn` 的基准实例保留订阅，重置时
  `onReset` 后按需重新启用；基准之外的实例移除或重置时释放订阅。
- 永久销毁、世界销毁或显式解绑时先停用再清理，仅一次；相同 ID 的新对象不继承旧回调。
- 原生临时角色的移除通知发生在引擎注销之后、动画资源退役之前；世界统一调用各注册项
  清理自身资源。物理移除、角色释放以及共享资产引用规则仍由原有所有者执行。
- 注册阶段失败清理后把原错误交还调用者；运行阶段错误记录实体与回调阶段，仅解除失败
  注册，继续其他资产与世界。清理异常不会阻断其他注册项。任意用户副作用不作事务回滚。
- 回调必须同步，不继承组件基类，不新增 Start/Awake 调度器、第二个 RAF、物理、动画或相机。
  不允许在回调内重入世界 step/dispose；复用既有作者写入与生命周期修改保护。

用法与完整边界见 [SDK 可选实体回调](../packages/three-world/README.md#optional-entity-lifecycle-callbacks)。
这不是资产库实现，也不自动替换已有角色或载具的动画逻辑。


## 本地完整门禁的运行环境

完整门禁按 [CI 环境](../.github/actions/setup-validation/action.yml) 在 Linux 上执行，
使用 Node 24.3.0、pnpm 10.14.0，并准备 Python、Pillow、requests、FFmpeg 和 Playwright。
Windows 可以运行类型、构建和游玩回归，但不能把 Linux 归档路径、符号链接、
目录文件描述符和 shebang 子进程检查在 Windows 上的失败直接判为 SDK 生命周期回归。
也不能跳过这些测试后声称完整门禁通过；应把同一份源码交给 Linux 环境复核。

Linux 验证副本必须核对源码字节与当前修改，并使用独立依赖和临时目录。
`TMPDIR` 应位于工作区之外，例如通过 `mktemp -d /tmp/worldkit-validation-XXXXXX` 创建。
项目声明 `type: module`；把临时夹具放进项目内，会让测试生成的无扩展名 CommonJS
假程序继承 ESM 规则，导致 `require` 失败，即使真正的生产可执行程序没有问题。

从仓库根目录运行 `pnpm test:independent`、`pnpm test:contract`、
`pnpm test:resource-heavy`；保留失败日志，复测结果与首次结果分开记录。
测试的超时不能通过重试成功、删断言或扩大预算来掩盖。

Episode 只使用 Lodash 的 `isEqual` 时直接导入 `lodash-es/isEqual.js`。
这是同一个实现，但避免工作流首次导入时加载总入口的全部工具模块。
冷启动开销应从实际模块依赖消除，保留 capture 用例的原有限时和行为断言。


全目录创建回归使用 960×600 的桌面视口，限制无 GPU runner 的纯栅格开销；
不缩小 campus 的物理地图、不停用模拟、不减少同场实体或实际按钮操作。
创建按钮禁用期间只轮询 DOM，完成后读取真实状态进行断言，避免等待期间反复
构造并传输全世界快照。单型号 20 秒和完整用例 150 秒限时保持不变。
