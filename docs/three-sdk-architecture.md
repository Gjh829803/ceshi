# Three SDK 设计与职责

目标是让 Agent 创建简洁可玩的白模，用户自然操作，并让 Episode 记录同一套动作，
供后续样式与视频数据生产使用。环境使用白色、浅灰基本体块和均匀基础照明；
少量关键标志物、交互目标加识别色。保留大体构图、尺度、空间关系和真实碰撞条件。
人形默认保留 `humanoid.source-101` 的可见模型、骨架和动作，无需添制服装或配饰。
其他主体优先复用提供的资源，没有合适的再自行绘制 Mesh 并绑定能力。
省去装饰细节、氛围、反射和复杂阴影，创作精力用于可玩功能。

## 四层使用方式

| 层级 | Agent 的工作 | 入口与结果 |
| --- | --- | --- |
| 直接复用 | 创建完整人物，选主体与能力 | `createHumanoidWorld({scene,camera,canvas,map})`；读取简短能力卡 |
| 场景与能力绑定 | 自制 Mesh；补碰撞、水体、攀爬面、交互锚点 | `TrainingMap`、`TrainingVehicleInstance`；自制地面主体用 `addCharacter` 的 `object/body/movement` |
| 参数配置 | 调速度、加速、滑行和镜头 | 带单位的 profile、movement 与按键配置；导出到项目 |
| 源码实现 | 修改动作、动画、碰撞或控制器 | `creator_materialize_runtime` 后修改项目 SDK 源码，重新编译与验证 |

公开类型与示例见 [SDK README](../packages/three-world/README.md)。同一资产可以复用
外观或完整能力，但一个 clip 名称不代表对应物理能力已接入。自制骨架需要兼容动画
映射；绑定地面移动不会自动产生四足步态或翅膀动画。

## 动作与输入契约

每张能力卡回答：用途、触发、人物条件、场景条件、参数、完成状态、失败原因和
源码入口。`training.characterCapabilities()` 返回实时可用性；动作定义、前置
检查、HUD 和工具说明复用同一份元数据。

例如滑铲由 **Shift + 新按 C/Ctrl** 触发，需要落地、站立、空手、无冲突/冷却、
实际速度至少 2.5 m/s。普通地面可以滑铲；低通道需要真实碰撞和足够助跑距离。
退出头顶空间不足时保持低姿态。详细条件见 SDK `character-actions` 主题。

默认操作是 WASD 移动、Shift 冲刺、Space 跳跃/翻越/起身、C/Ctrl 蹲伏、Z 匍匐、
Q 翻滚、E 交互、G 放下、F 上下载具。控制表统一生成提示和录制可用按键；
用户可以重绑，Agent 使用语义输入或动作请求。E 优先选择当前交互目标，再尝试
攀爬。动画过渡不分配独立按键。

Agent 读取动作可用性与目标位置，先通过真实输入接近，再提交动作。`accepted`
表示开始，最终操作状态和 snapshot 决定是否完成。碰撞、拒绝和超时也进入证据。

## 执行职责

| 内容 | 唯一执行者 | 作者可以修改什么 |
| --- | --- | --- |
| 外观与场景 | 普通 Three.js | Mesh、Group、材质、光照、视觉子对象 |
| 物理、支撑与重力 | SDK 选定的 Rapier 后端 | 碰撞描述、参数或该模块源码 |
| 角色运动与动画 | SDK 角色控制器和动画模块 | 输入、动作配置、兼容绑定或模块源码 |
| 镜头 | 当前相机模式的写入者 | 初始构图、跟随参数、模式或模块源码 |
| 模拟与生命周期 | SDK 固定时钟 | 通过 start/stop/reset/commands 操作 |
| UI、模型输入/输出 | Presentation 和应用 | HTML UI、传输和真实源帧映射 |
| 编译、自检与交付 | Creator Host | 项目源码；Host 验证不属于作品运行时 |
| 规划、录制、样式 | Episode Host 与阶段 Agent | 动作目标、路线、样式计划 |

修改底层是在项目运行时构建内替换对应模块，仍保持每项状态一个写入者。
场景代码不额外创建物理世界、模拟循环或相机跟随。运行时源码与实际字节共同进入
交付身份，便于复验与独立消费。

## 画面与生产

`world.createPresentation()` 将纯世界输入、模型输出和 DOM UI 分开。模型返回
真实源帧身份后，HUD 才能对应历史状态；未知映射不能靠猜测固定延迟补齐。
重置使源帧身份失效。

Creator 用完整的真实输入计划覆盖核心功能及动作结果，录制长度由覆盖需要决定。
提交包含自检录像、开场、重要对象三视图和源码/运行时身份。
Episode 在独立生产副本中，用同一 SDK 记录六段 30 秒动作，之后制作十套风格。
录制中每帧来自真实模拟，动作事件来自执行证据。视频请求准备完成与最终视频完成
分别表达；执行范围见 [数据生产](three-sdk-data-production.md)。

## 验证

先检查接口消费者和场景条件，再验证真实输入、动作转换、失败结果、reset 和录制。
Creator 和 Episode 都要验证，某一侧通过不替代另一侧。运行时检查见
[专项检查表](reviews/runtime-deep-review-checklist.md)；纯文档检查链接、声明和
schema 主题提取。云任务、部署和外部审核依照实际任务授权执行。
