# GPT-6 Creator 五例独立评测 · 2026-09-05

评测入口：[打开试玩平台](http://k8s-lwdp-worldkit-1b0222fb6d-f0f26ee23663e783.elb.us-east-2.amazonaws.com/creator-evals/)。

本轮固定五张原图与原始/有效 prompt，以 GPT-6 xhigh、不可变 V3
Runtime 运行。平台保留原始交付，即使存在明确缺陷也开放试玩并标注问题。
这份评测将云端链路、浏览器部署、内容质量分别记录；不会用自动测试通过
替代对参考图、主体和真实通路的判断。

耗时是单次云端执行时间的近似值，不含前置旧 CLI/MCP 配置探针，也不将
账户排队算作模型推理。四个后续 job 的提交并发上限为 4；宫殿首次请求
因共享账户槽等待，在确认取消终态后以同原图、同 prompt、同 V3、新 request
重开，只调整请求的账户并发数。精确 job/attempt 时间以 cloud summary 为准。

录像采样率为 1–2 fps，属于检查证据，不是网页实际运行帧率。
3–5 分钟自动路线仍不足以证明整个承诺世界都可达、有趣或没有 Bug。

## 关键复现

**森林**：独立输入到达并跨越梯子所在平面，主体仍停在 `y≈0.05m`，
跳跃最高 `1.58m`，平台顶面 `10.35m`。实际 collider 只有三块地面及高台，
梯子既没有运动能力绑定，也没有可走的替代坡道。三条声明地面路线全部
通过，恰好说明路线选择没有覆盖用户真正关心的塔楼。

**梯田**：沿输入走到入口阶梯、中央田、右侧高田、最高田，主体一直位于
`y≈0.05m`，对应可见表面分别在 `0.65/0.85/3.45/4.4m`。
Runtime audit 唯一 collider 为 `base-ground`；可见梯田、台阶和坡道均为
`physics:none`。截图证实穿过阶梯和进入高地下面，而非单纯参数推测。

**九尾狐**：主体前进 `11.53m` 后，九尾、胸饰和耳朵仍在出生点。
模型将这些部分注册成独立静态世界 Mesh，没有绑定受控主体。主体三视图
还显示了三个大小不同的方块四足样板，无法视为一只符合参考的九尾狐。

这些检查均运行封存后的真实 bundle，比较检查前后文件 SHA；没有手工
修改场景后重新命名为模型交付。浏览器基础操作通过与内容质量失败并存。

## 对 Agent/SDK 的结论

本轮已经证明云端 Codex 能调用真实工具、看真实截图、修改 Native 场景、
运行 SDK 控制器、交付三视图和完整静态试玩包。**尚未证明目前的轻量
合同能够稳定生成符合用户要求的世界。** 这不是受控 GPT-5.6/GPT-6 对比，
不能把结果归因为模型能力的升降。

下一轮优先补以下可验证辅助，而非恢复固定方块/统一构图政策：

1. **精确错误反馈与最小示例**：森林多轮只得到泛化构建错误，最终简化掉
   关键地形。给出出错规范、正确导入和 Material/实体注册示例，让模型能
   定点修复；本地后续源码已开始补充，不能算到这次冻结 V3 的表现中。
2. **可见地形与支撑检查**：针对参考图要求的台阶、桥、坡道、高台指定
   检查目标，观察真实主体脚底与可见表面，不仅统计在底层平面上走过多少格。
3. **清晰的主体与附件能力**：素材目录要显示实际完整外观与组成；主体
   附件需要明确跟随关系。静态世界装饰不能替代随主体移动的尾巴、衣物。
4. **完整对象分组与语义朝向**：塔楼不应只捕获平台，祭坛不应只捕获底盘；
   三视图必须覆盖完整对象，正/右/背标记与实际语义朝向相符。
5. **独立首帧/玩法评审**：模型自测与 Host 操作检查均不能替代最终用户
   试玩评分。当前 orbit 相机也尚未覆盖任意独立首帧位姿和偏构图。
