# 输入系统与用户习惯键位整理

状态：输入系统 1.5 基础功能、姿态与镜头先在本地 Playground 落地；验证结果见
[开发计划与验收记录](superpowers/plans/2026-09-16-input-system-1-5-pitch-decoupling.md)。

网页端飞书 [input-system-1-5-key-matrix](https://icnimsatr0zz.feishu.cn/sheets/DDQSsQetShZUDqtXUKccuOAanUd)
的 `1.5键位矩阵（俯仰解耦）`（sheet `C6ibZf`）是产品键位权威来源。本次于 2026-09-16 通过飞书 CLI 读取
revision **408**，并以随后用户确认的固定翼 Q 俯/E 仰、Space 地面刹车及翼装穿脱规则为准；不修改飞书，不维护独立 xlsx 副本。本文维护实现范围和运行时合同，
不复制完整产品矩阵。

人物 Ctrl 按住慢走、不切换蹲伏已包含在新表。双轴对象 Q/E 升降、Space/C 俯仰；仅有独立俯仰的固定翼使用 Q 俯/E 仰。表第 2 行仍写统一 Space/C 俯仰，第 16 行仍保留 Shift 牵引/助跑，均以本轮用户确认覆盖，不回写飞书。

## 1. 本轮边界

纳入 W/A/S/D、Shift、Ctrl、Space、F、Q/E、C、Z/X、方向键、V、H 和长按 Backspace。
只连接已经存在的对象能力；没有消费者的按键保持无副作用。

交付范围仅为本地 Playground 及其依赖的共享 SDK，不做 Creator / Episode 适配、
跨端验收或发布。共享 SDK 的默认键位与语义仍会影响其他消费者，不能据此宣称
Creator / Episode 已兼容；接入这些消费者前须单独迁移和验证。

以下仍是后续目标，不得由本轮实现推断为已支持：

- 射击、RMB 瞄准、鼠标瞄准方向、换弹、装备槽、投掷、收武器、射击模式。
- **F1-F4 换座**与多座乘员/驾驶权；不再使用 Ctrl+数字方案，1-5 留给未来装备槽。
- 移动端虚拟按钮改版、离线资产静态说明的批量迁移；本地 HUD 键位提示已在后续阶段对齐。
- 新喇叭和载具叫声；H 当前只在人物状态调用已有召唤飞龙能力。

既有程序化能力（例如飞龙喷火）未删除，但本轮不为它新增键盘或鼠标入口。
放下物体与拾取统一使用 F 场景交互；放下动作仍保留为语义动作能力，但不再默认占用 G。

载具回正/脱困是 F 交互语义的后续扩展：当载具实际处于翻车或持续阻挡状态时，
回正/脱困优先于上车或下车；具体状态判定、安全放置和脱困搜索见
[载具回正与 F 键优先级方案](vehicle-recovery-input-plan.md)。当前 SDK 运行时已接入该
优先级、状态快照和 Playground 提示；Creator / Episode 的独立验收仍按下文安排。

## 2. 保守实现与唯一所有者

沿用 `WorldKeyboard → WorldInput → HumanoidRuntime → motion family`，不新增输入框架、
事件总线、物理循环或相机 writer。键盘上下文只补充 `mode`、`aircraftSubtype` 和
`instanceId`，并读取翼装的地面控制与开伞事实，用于区分飞机子类、输入阶段及清理对象切换后的旧按键。

- `config/input.ts` 维护默认键位；`getKeyBindings` / `setKeyBindings` 仍是公开入口。
- `pitchUp` / `pitchDown` 默认 Space/C，`ascend` / `descend` 默认 Q/E；滑翔 `airbrake` 单独保留 C，人物/普通坐骑 `jump` 仍是 Space。按上下文启用，不做全局键码互换。
- 固定翼专用 `fixedWingPitchDown` / `fixedWingPitchUp` 默认 Q/E，与双轴对象的俯仰绑定分开重绑；仍输出同一个程序化 `pitch` 轴，不新增输入执行器。
- 冲突按有效上下文检查：人物 Ctrl 慢走与挂载 Ctrl 减速复用 `slow`，C 单独蹲伏；同上下文的两个
  动作不能消费同一个键。旧 `vehicle` 绑定合并为 `interact`，默认 E 改 F、T 改 V。
- 失焦、进入 UI、页面隐藏、重绑、控制对象切换和复位会清理 held/edge 状态。
- Playground 使用 SDK 入口，不增加应用级玩法监听器；其他消费者的迁移留到后续阶段。

## 3. F、V 和 Backspace

**F 是统一交互按下沿。** F 的具体动作由当前主体、最近目标和载具状态共同决定。
当当前驾驶载具，或人物交互范围内的最近载具，实际处于 `flipped` / `stuck` 状态时，
先尝试载具回正/脱困；成功后保持原控制关系，下一次 F 才继续执行下车或上车。
回正/脱困失败也消费本次 F，不在同一按键沿上继续执行上下车。

载具是否具备飞行能力不等于当前是否正在飞行：飞机在正常空中飞行/翻滚时保持现有
飞行交互，飞机已经落地、侧翻或倒扣时参与地面翻车判断。若飞机持续有驾驶输入却
完全没有位移，说明可能穿入建筑或碰撞代理失配，累计阻挡时间后按 `stuck` 提供脱困。
普通载具短暂离地、正常停车、主动刹车或没有驾驶输入时，不因为 `grounded=false` 或
速度为零就触发回正/脱困。

没有回正/脱困候选时，已挂载对象沿用原有离开对象、请求飞龙着陆或其他专属交互；
人物已有场景动作、坐姿、搬运、攀爬或附近场景目标时交给人物交互，否则有可乘目标
才交给登乘 owner。一次输入只选择一个 owner，不在失败后再执行另一种动作。距离、
速度、净空和动作资源资格仍由现有系统检查，不因统一按键而放宽。

**V 是视角切换按下沿。** 只提交现有 `cameraTogglePressed`，由 CameraDocument
决定可循环视角，不直接写相机位姿。

**Backspace 只在挂载状态生效。** 累计实际模拟固定步达到 0.8 秒后，在该步提交完毕后
触发现有 reset callback，一次长按只触发一次。keyup、焦点/上下文变化取消计时。
读取、截图、零步观察及程序化显式输入不会推进键盘长按计时。
Backspace 仍表示整套场景/主体复位，不替代 F 的当前载具回正/脱困；F 的局部恢复
必须沿用同一 SDK 物理 owner 和安全检查。
Playground 不再用 R 作为旁路复位键，原按钮保留。

## 4. 移动、姿态与升降

`forward`、`steer`、`pitch`、`roll`、`lift` 为归一化轴，相反按键相抵；
`boost`、`slow`、`brake` 沿用布尔字段，但各控制族解释不同。

| 字段 / 默认入口 | 运行时解释 |
| --- | --- |
| `forward` / W-S | 人物前后；地面/船只驱动；固定翼持续油门增减；旋翼目标前后速度；滑翔目标空速配平；飞龙前进/减速；飞船推进 |
| `steer` / D-A | 人物左右移动；载具转向或偏航 |
| `pitch` / Q-E 或 C-Space | 正值低头、负值抬头；固定翼 Q/E，飞龙、潜艇和飞船 C/Space |
| `roll` / X-Z | 飞船横滚，旋翼/倾转侧倾侧移，坦克炮塔水平转动，悬浮载具侧移；固定翼/潜艇/滑翔键盘不消费 |
| `lift` / Q-E；滑翔 C | Q 上升/上浮、E 下降/下潜；旋翼改变持续垂直速度需求，热气球加热/放热；滑翔 C 单独保留扰流/下降辅助，不启用 Q/E |
| `boost` / Shift | 人物和地面翼装可选跑步，动力载具辅助加速；滑翔飞行、飞船、热气球键盘不消费。程序化有限牵引入口保留 |
| `slow` / Ctrl | 人物按住慢走、不改变姿态；挂载减速，地面/水面复用原制动，坐骑慢速，飞船反推，固定翼降油门，旋翼水平减速；热气球键盘不消费 |
| `brake` / Space | 地面对象与动力固定翼/尾推制动、滑翔着陆/开伞特殊动作；人物/坐骑及地面翼装 Space 是跳跃 |

对象差异：

- 人物 Ctrl+WASD 按住慢走，复用控制器 `slowSpeed`；松开恢复普通移动或仍按住的 Shift 冲刺，两者同时按时慢走优先。单按 Ctrl 不移动，也不切换姿态。C 蹲伏切换，Shift+C 保留已有助跑滑铲；Z 匍匐，Q 翻滚。
- 普通坐骑 Space 通过既有跳跃速度和碰撞路径跳跃；马车不新增跳跃。
- 飞龙 Space/C 抬头/低头，Q 按下沿起飞、按住上升，E 下降；Z 调用闪避，X 不消费。姿态、升降与 Ctrl 独立，S 不产生空中倒飞。
- 固定翼 Q 低头/E 抬头，Space 恢复地面刹车，C 与 Z/X 空闲。Ctrl 优先于同时按下的 W/Shift，避免减油门/制动时仍增加油门。
- 旋翼 Q/E 通过既有持续垂直需求工作：50% 悬停、零位关机；Ctrl 不降低集体升力；Space/C 留空。
- 旋翼/倾转 Z/X 请求侧倾，通过旋翼合力侧移；松键回正不承诺主动停漂。倾转巡航按 Ctrl 或 S 会逐渐恢复朝上的旋翼，交由原飞控减速，不直接覆盖速度。
- 滑翔机 W 发起限时牵引，滑翔伞 W 助跑；飞行后 W/S 配平空速，不生成发动机推力。已释放牵引不能在空中靠 W 再次触发；S 地面减速，Ctrl/Space 制动优先。
- 翼装 F 穿戴后地面复用人物 WASD、Shift 跑步、Ctrl 慢走和 Space 跳跃；真实下落持续 0.15 秒且离地超过 3 米才切入飞行，普通跳跃不触发。Space 重新按下才开伞，伞下可按住制动。地面 F 脱下；飞行落稳收伞后自动脱下并平放原地。再次 F 穿戴清除上次飞行状态，不传回高台，不限制平地穿戴，也不提供平地起飞。
- 滑翔类无独立俯仰/横滚键，Q/E 与 Z/X 留空；Space 特殊动作、C 扰流保留。固定翼无手动横滚键，A/D 自动侧倾转弯保留。取消默认键不删除程序化 `pitch` / `roll` 能力。
- 潜艇俯仰与升降独立；Ctrl 制动，Shift 请求已有动力系统的推进增强。
- 热气球水平随风；Q 加热，E 放热，Space/C 留空，方向键只观察。
- 飞船左右方向键不再侧移；程序化 `strafe` 字段保留。

各族公开说明位于
[`input-guidance.ts`](../packages/three-world/src/humanoid-runtime/input-guidance.ts)，
可用 `world.describe().humanoid.inputGuide` 查询当前族。Playground 使用的 aircraft
语义动作已迁移：俯仰填 `pitch`，固定翼油门填 `forward`，升降/热气球填 `lift`。
Episode 的路径控制器本轮未迁移；后续必须调整旧调用者，不能继续把飞机 `forward`
当俯仰、把潜艇/飞船 `boost` 当制动。这是待处理的兼容性缺口，不属于本轮完成项。

## 5. 方向键、相机与指针

所有对象的 ↑↓←→ 只观察，不生成载具姿态输入；俯仰、升降键也不附带相机 orbit。
飞行/潜水/太空上下观察保留原 20% 速率（热气球除外），但解除相对开场/默认角度的
上下各 10° 额外限制。长按可以跨过旧边界，最终仍受当前 CameraDocument 的正常俯仰
范围、极点保护和碰撞约束；不允许无限翻转或穿模。普通人物等的原速率不变。
相机仍由同一个 owner 写入；左键向左看、右键向右看，重绑后同样解耦。

载具第三人称默认在松开观察输入 1.5 秒后缓慢回正；项目快照和飞龙变体的回正速度门槛改为 0，静止/悬停也回正。人物、第一人称、过肩及 SDK 通用默认门槛不改。持续按观察键时仍暂停回正。
连续航向用实际机体前向校正，仅用帧间旋转选择连续分支，防止俯仰与翻滚组合后累计虚假偏航；倒飞过极点连续性保留，恢复正飞后重新对齐真实机头。
本次不把所有相机改为跟随机体俯仰/横滚：多数载具第三人称保持世界水平，飞船继续使用自身配置的主体上方向与独立偏航。

为降低风险，本轮保留既有鼠标/触摸拖拽路由，验证其没有退化；不把它认定为 RMB 瞄准。
以后做射击时再明确鼠标瞄准与触摸观察的状态/消费关系。
移动端和手柄后续提交同一设备无关轴，不模拟 PC 键码。PC 精确瞄准优先鼠标，
RMB 只切换瞄准状态；这一产品决定不要求本轮建立新 schema。

## 6. HUD 与后续工作

本地 Playground 的快捷键栏、镜头说明及当前操作提示已按实际控制族/飞机子类型对齐。
按键读取 `getKeyBindings()`；切换对象或重绑时刷新，不再把 `plane` 都显示成固定翼，
也不再用资产里的旧 `spec.hint` 作为当前飞机操作提示。翼装的状态提示使用同一组绑定。

- 固定翼/尾推：W/S 增减持续油门；Q/E 低头/抬头，Space 地面刹车，C 与 Z/X 不消费；Ctrl 减油门/地面
  制动；Shift 仍有真实的辅助加油门作用，单独标注，不能把它写成主要油门入口。
- 旋翼：W/S 前后飞行、Q/E 垂直需求、Z/X 侧倾侧移、Ctrl 水平制动；滑翔保留 W/S 空速配平及 Space/C 既有特殊动作/扰流；热气球 Q/E 加热/放热。
- 潜艇/飞船不再把 Shift 标成制动或把 Ctrl 标成下降；坦克不再显示方向键炮管瞄准。
- 视角切换使用当前绑定（默认 V），挂载时提示长按 Backspace 场景复位；方向键左右
  表示视线左右转向。人物 F 拾取/放下沿用另一任务的最新实现，不恢复旧 G 提示。

载具回正/脱困接入后，HUD 必须读取 SDK 的实时状态而不是自行根据姿态推断：正常
载具显示上车/下车，`flipped` 或 `stuck` 且可安全处理时显示回正/脱困，实际
`airborne` 时继续显示原有飞行交互。载具确实翻车或卡住但当前没有安全落点时，
显示失败原因，不显示可执行的回正提示。

本轮不改 HUD 布局或移动端虚拟按钮。离线资产元数据仍可能有旧说明，
未批量重写；Creator / Episode 仍未迁移。数字 1–6 仍是 Playground 调试用“快速前往”，
不表示技能阶段的装备槽已经实现。

技能阶段单独实现 F1-F4 与座位模型、装备槽、瞄准/开火；不因表格已有单元格而假定
对应消费者存在。飞书表头 `1/2/3/`、RMB 拼写等显示格式不影响本轮执行。

## 7. 验证要求

依据 [运行时检查表](reviews/runtime-deep-review-checklist.md) 验证默认/重绑输入、
一次性边沿、冲突、状态清理、实际运动及相机消费，不只检查键码解析。
重点覆盖 Ctrl/C 分离、W/S/俯仰分离、F 单 owner、F 回正/脱困优先级、V、0.8 秒复位、
热气球空键、对象切换，以及本地 Playground 的实际输入路径。回正/脱困还要覆盖落地
飞机、短暂离地、建筑阻挡、回正失败和长按 F 不重复执行。Creator / Episode 验收另行安排。

本轮 SDK 测试、类型检查、清单检查和 Playground build 的结果记录在
[开发计划](superpowers/plans/2026-09-16-input-system-1-5-pitch-decoupling.md)，
环境限制与失败不得伪装为通过。未启动云端任务、发布或修改外部生产记录。
