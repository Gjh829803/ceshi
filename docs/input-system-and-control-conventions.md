# 输入系统与用户习惯键位整理

状态：输入系统 1.5 基础功能、姿态与镜头先在本地 Playground 落地；验证结果见
[开发计划](superpowers/plans/2026-09-16-input-system-1-5-foundation-and-camera.md)。

网页端飞书 [input-system-1-5-key-matrix](https://icnimsatr0zz.feishu.cn/sheets/DDQSsQetShZUDqtXUKccuOAanUd)
的 `1.5 键位矩阵` 是产品键位权威来源。本次于 2026-09-16 通过飞书 CLI 读取
revision **283**，不修改飞书，不维护独立 xlsx 副本。本文维护实现范围和运行时合同，
不复制完整产品矩阵。

## 1. 本轮边界

纳入 W/A/S/D、Shift、Ctrl、Space、F、Q/E、C、Z、方向键、V、H 和长按 Backspace。
只连接已经存在的对象能力；没有消费者的按键保持无副作用。

交付范围仅为本地 Playground 及其依赖的共享 SDK，不做 Creator / Episode 适配、
跨端验收或发布。共享 SDK 的默认键位与语义仍会影响其他消费者，不能据此宣称
Creator / Episode 已兼容；接入这些消费者前须单独迁移和验证。

以下仍是后续目标，不得由本轮实现推断为已支持：

- 射击、RMB 瞄准、鼠标瞄准方向、换弹、装备槽、投掷、收武器、射击模式。
- **F1-F4 换座**与多座乘员/驾驶权；不再使用 Ctrl+数字方案，1-5 留给未来装备槽。
- 移动端虚拟按钮改版、离线资产静态说明的批量迁移；本地 HUD 键位提示已在后续阶段对齐。
- 新喇叭和载具叫声；H 当前只在人物状态调用已有召唤飞龙能力。

既有程序化能力（例如飞龙喷火）未删除，但本轮不为它新增键盘或鼠标入口。
放下物体与拾取统一使用 F 场景交互；放下动作仍保留为语义动作能力，但不再默认占用 G。

## 2. 保守实现与唯一所有者

沿用 `WorldKeyboard → WorldInput → HumanoidRuntime → motion family`，不新增输入框架、
事件总线、物理循环或相机 writer。键盘上下文只补充 `mode`、`aircraftSubtype` 和
`instanceId`，用于区分飞机子类及清理对象切换后的旧按键。

- `config/input.ts` 维护默认键位；`getKeyBindings` / `setKeyBindings` 仍是公开入口。
- 冲突按有效上下文检查：人物 C/Ctrl 蹲伏与挂载 Ctrl 减速可以复用，同上下文的两个
  动作不能消费同一个键。旧 `vehicle` 绑定合并为 `interact`，默认 E 改 F、T 改 V。
- 失焦、进入 UI、页面隐藏、重绑、控制对象切换和复位会清理 held/edge 状态。
- Playground 使用 SDK 入口，不增加应用级玩法监听器；其他消费者的迁移留到后续阶段。

## 3. F、V 和 Backspace

**F 是统一交互按下沿。** 已挂载时只尝试离开对象或请求飞龙着陆；人物已有场景动作、
坐姿、搬运、攀爬或附近场景目标时交给人物交互，否则有可乘目标才交给登乘 owner。
一次输入只选择一个 owner，不在失败后再执行另一种动作。距离、速度、净空和动作资源
资格仍由现有系统检查，不因统一按键而放宽。

**V 是视角切换按下沿。** 只提交现有 `cameraTogglePressed`，由 CameraDocument
决定可循环视角，不直接写相机位姿。

**Backspace 只在挂载状态生效。** 累计实际模拟固定步达到 0.8 秒后，在该步提交完毕后
触发现有 reset callback，一次长按只触发一次。keyup、焦点/上下文变化取消计时。
读取、截图、零步观察及程序化显式输入不会推进键盘长按计时。
作用域沿用 Host 的既有 reset/recovery 生命周期，不新增“只修复当前车辆”的系统。
Playground 不再用 R 作为旁路复位键，原按钮保留。

## 4. 移动、姿态与升降

`forward`、`steer`、`pitch`、`roll`、`lift` 为归一化轴，相反按键相抵；
`boost`、`slow`、`brake` 沿用布尔字段，但各控制族解释不同。

| 字段 / 默认入口 | 运行时解释 |
| --- | --- |
| `forward` / W-S | 人物前后；地面/船只驱动；固定翼持续油门增减；旋翼目标前后速度；滑翔目标空速配平；飞龙前进/减速；飞船推进 |
| `steer` / D-A | 人物左右移动；载具转向或偏航 |
| `pitch` / ↓-↑ | 正值低头、负值抬头；不再由 W/S 直接产生 |
| `roll` / E-Q | 横滚；坦克为炮塔水平转动，悬浮载具为侧移 |
| `lift` / Space-C | 垂直对象升降；旋翼改变持续垂直速度需求；热气球加热/放热；滑翔类 C 为扰流/下降辅助 |
| `boost` / Shift | 冲刺、加速、牵引/助跑；飞船、热气球键盘不消费 |
| `slow` / Ctrl | 挂载减速；地面/水面复用原制动，坐骑慢速，飞船反推，固定翼降油门，旋翼水平减速；热气球键盘不消费 |
| `brake` / Space | 非直接垂直对象的地面制动、滑翔着陆/开伞特殊动作；人物/坐骑 Space 则是跳跃 |

对象差异：

- 人物 C/Ctrl 蹲伏切换；Shift+C/Ctrl 保留已有助跑滑铲。Z 匍匐，Q 翻滚。
- 普通坐骑 Space 通过既有跳跃速度和碰撞路径跳跃；马车不新增跳跃。
- 飞龙 Q 调用闪避，E 不消费；Space/C 与 Ctrl 独立，S 不产生空中倒飞。
- 固定翼 C 未使用；Ctrl 优先于同时按下的 W/Shift，避免制动时仍增加油门。
- 旋翼 Space/C 通过既有持续垂直需求工作：50% 悬停、零位关机；Ctrl 不降低集体升力。
- 滑翔 W/S 通过配平影响空速，不生成发动机推力；Shift 受牵引/助跑条件限制。
- 潜艇俯仰与升降独立；Ctrl 制动，Shift 请求已有动力系统的推进增强。
- 热气球水平随风；Space 加热，C 放热，方向键只观察。
- 飞船左右方向键不再侧移；程序化 `strafe` 字段保留。

各族公开说明位于
[`input-guidance.ts`](../packages/three-world/src/humanoid-runtime/input-guidance.ts)，
可用 `world.describe().humanoid.inputGuide` 查询当前族。Playground 使用的 aircraft
语义动作已迁移：俯仰填 `pitch`，固定翼油门填 `forward`，升降/热气球填 `lift`。
Episode 的路径控制器本轮未迁移；后续必须调整旧调用者，不能继续把飞机 `forward`
当俯仰、把潜艇/飞船 `boost` 当制动。这是待处理的兼容性缺口，不属于本轮完成项。

## 5. 方向键、相机与指针

| 当前对象 | ↑ / ↓ | ← / → |
| --- | --- | --- |
| 人物、普通坐骑、地面/水面载具、坦克、热气球 | 相机观察 | 相机观察 |
| 飞龙、潜艇、飞船、固定翼、旋翼/倾转、滑翔类 | 载具 `pitch`，附带小幅镜头跟随 | 相机观察 |

实时键盘的飞行俯仰附带 20% 观察速率的镜头跟随，相对当前视角默认俯仰（或保留开场角度）
限制在上下各 10°。长按到边界后镜头停止偏移，载具仍接收完整俯仰输入；鼠标和显式程序化
观察沿用 CameraDocument 限制。相机仍由同一个 owner 写入。左右键按视线转向解释，
左键向左看、右键向右看。坦克方向键只观察；重绑后仍执行相同上下文分配。

为降低风险，本轮保留既有鼠标/触摸拖拽路由，验证其没有退化；不把它认定为 RMB 瞄准。
以后做射击时再明确鼠标瞄准与触摸观察的状态/消费关系。
移动端和手柄后续提交同一设备无关轴，不模拟 PC 键码。PC 精确瞄准优先鼠标，
RMB 只切换瞄准状态；这一产品决定不要求本轮建立新 schema。

## 6. HUD 与后续工作

本地 Playground 的快捷键栏、镜头说明及当前操作提示已按实际控制族/飞机子类型对齐。
按键读取 `getKeyBindings()`；切换对象或重绑时刷新，不再把 `plane` 都显示成固定翼，
也不再用资产里的旧 `spec.hint` 作为当前飞机操作提示。翼装的状态提示使用同一组绑定。

- 固定翼/尾推：W/S 增减持续油门；上下方向键俯仰并有限镜头跟随；Ctrl 减油门/地面
  制动；Shift 仍有真实的辅助加油门作用，单独标注，不能把它写成主要油门入口。
- 旋翼：W/S 前后飞行、Space/C 垂直需求、Ctrl 水平制动；热气球只提示已有的加热/放热。
- 潜艇/飞船不再把 Shift 标成制动或把 Ctrl 标成下降；坦克不再显示方向键炮管瞄准。
- 视角切换使用当前绑定（默认 V），挂载时提示长按 Backspace 场景复位；方向键左右
  表示视线左右转向。人物 F 拾取/放下沿用另一任务的最新实现，不恢复旧 G 提示。

本轮不改 HUD 布局、移动端虚拟按钮或控制执行逻辑。离线资产元数据仍可能有旧说明，
未批量重写；Creator / Episode 仍未迁移。数字 1–6 仍是 Playground 调试用“快速前往”，
不表示技能阶段的装备槽已经实现。

技能阶段单独实现 F1-F4 与座位模型、装备槽、瞄准/开火；不因表格已有单元格而假定
对应消费者存在。飞书表头 `1/2/3/`、RMB 拼写等显示格式不影响本轮执行。

## 7. 验证要求

依据 [运行时检查表](reviews/runtime-deep-review-checklist.md) 验证默认/重绑输入、
一次性边沿、冲突、状态清理、实际运动及相机消费，不只检查键码解析。
重点覆盖 Ctrl/C 分离、W/S/俯仰分离、F 单 owner、V、0.8 秒复位、热气球空键、
对象切换，以及本地 Playground 的实际输入路径。Creator / Episode 验收另行安排。

本轮 SDK 测试、类型检查、清单检查和 Playground build 的结果记录在

环境限制与失败不得伪装为通过。未启动云端任务、发布或修改外部生产记录。
