# 输入系统与用户习惯键位整理

状态：1.5 目标方案。网页端飞书表格
[input-system-1-5-key-matrix](https://icnimsatr0zz.feishu.cn/sheets/DDQSsQetShZUDqtXUKccuOAanUd)
的 `1.5 键位矩阵` 是键盘按键与对象动作映射的权威来源；本文件只维护当前实现基线、
设备适配、运行时语义和实施验证，不再保存独立的 xlsx 副本，也不重复维护一份完整矩阵。

本文按 2026-09-16 读取到的飞书 revision 222 整理。目标方案尚未落到运行时代码；
凡是“当前”与“目标”并列出现的地方，都不能把目标文案当作已经可执行的能力。

## 1. 已确认的产品取舍

1. **F 是统一上下文交互键。** 场景交互、上下载具、上下坐骑、上下飞龙和上下飞船
   都由当前对象与目标上下文解释。E 不再承担全局交互，因此可以留给横滚或对象特殊动作。
2. **Ctrl 的基础职责是减速，但允许对象级覆盖。** 载具中表示减速、制动或精细操控；
   人物中保留 C / Ctrl 蹲伏的既有习惯，人物状态不再消费 Ctrl 减速。
3. **W/S 优先表达前后、速度或油门。** 飞行器不再用 W/S 直接控制俯仰；A/D 维持
   左右移动或转向，Q/E 按对象解释横滚、炮塔、侧移或特殊动作。
4. **方向输入以跨设备的观察轴建模。** PC 普通观察可用方向键；移动端使用右侧虚拟摇杆
   或屏幕拖动；手柄使用右摇杆。对飞行器、潜艇、飞龙和飞船，观察轴的垂直分量还会
   派生俯仰需求，但不能由两个互不知情的监听器分别写镜头和载具。
5. **精确瞄准在 PC 上优先使用鼠标。** RMB 只负责进入或保持瞄准状态，鼠标移动负责
   瞄准方向；方向键是键盘备用。移动端仍把同一观察/瞄准轴映射到右摇杆或拖动，
   因而 PC 鼠标绑定不会形成移动端依赖。
6. **Ctrl + 数字保留为换位。** 参考常见载具射击游戏的操作，1/2/3/4/5 继续保留装备槽
   语义；载具换位使用组合键。组合键优先于单键：识别到有效数字后，本次组合不得同时
   产生 Ctrl 减速和数字装备切换。
7. **HUD 显示对象动作，不显示兼容字段名。** 同一个 `slow`、`boost`、`roll` 或
   `forward` 字段在不同控制族中可以有不同实现，但 HUD、资产提示和 AI-facing contract
   必须显示当前对象真实动作。

## 2. 权威来源与同步边界

飞书矩阵负责以下内容：

- 对象类型与物理按键的目标映射；
- `—` 所表示的未消费按键；
- 每个对象在 W/A/S/D、Shift、Ctrl、Space、F、Q/E、C、Z、方向键、V、H、
  Backspace、R、鼠标键、数字键、Ctrl + 数字、X、B 上的用户动作名称。

本文件负责以下内容：

- 当前运行时与目标矩阵的差异；
- 同一物理键如何转换为设备无关意图和对象语义；
- HUD、Creator、Episode 与移动端适配要求；
- 实施顺序、受影响消费者和验证边界。

同步时应用以下录入规范，但不改变动作含义：

- 表头 `1/2/3/` 统一写作 `1 / 2 / 3`；
- 空白或只含空格的未使用单元格按 `—` 解释；
- `BackSpace` 在文档与代码说明中统一写作 `Backspace`；
- 飞书第 2 行是摘要，具体对象行优先。例如固定翼和滑翔类的 Space/C 是刹车、
  开伞、着陆或扰流板等特殊动作，不能被摘要中的“上升/下降”覆盖；
- “近战”必须在 HUD/能力说明中区分“选择近战槽”与“立即近战攻击”。当前矩阵的
  4 键按装备槽解释，实际攻击仍由 LMB 或显式动作完成。

## 3. 输入分层与设备映射

输入系统必须分开表达三层，不把 DOM 键名直接传遍所有控制器：

```text
物理设备输入  →  设备无关意图  →  当前对象语义动作
Keyboard          look / move       throttle / pitch / turretYaw
Mouse             aim / primary     aimDirection / fire
Touch             virtual sticks    cameraLook / vehiclePitch
Gamepad           sticks/buttons    object-specific actions
```

物理键只在入口层出现。运行时模式适配器根据人物是否挂载、`vehicle.mode`、
`archetype`、飞行器子类型和动作状态解释意图；相机、人物控制器和载具控制器仍各有
唯一写入者。

### 3.1 观察、俯仰与瞄准

建议统一使用二维观察意图，名称以实际公共 schema 为准：

```text
lookX  水平观察速率或位移
lookY  垂直观察速率或位移
```

设备映射：

| 设备/状态 | lookX / lookY 来源 | 说明 |
| --- | --- | --- |
| PC 普通观察 | 方向键；可选鼠标 | 方向键是无鼠标和键盘操作的默认路径 |
| PC 瞄准 | 鼠标优先，方向键备用 | RMB 只改变瞄准状态，不提供方向 |
| 移动端 | 右侧虚拟摇杆或屏幕拖动 | 不复用 PC 键码，提交同一观察轴 |
| 手柄 | 右摇杆 | 按平台曲线处理死区和响应 |

三维对象单元格中的“镜头上下 / 俯仰”表示耦合的用户体验，不表示同一键盘事件要被
相机和载具各监听一次。目标链路是：

```text
方向键 / 右摇杆 / 拖动
          ↓
      lookY 意图
       ↙       ↘
相机 owner     当前三维对象适配器
提交观察角      派生 pitchDemand
```

对象适配器可以直接消费 `lookY`，也可以从已提交的观察方向派生俯仰需求；二者只能选
一条明确路径。相机跟随负责把载具姿态反馈到画面，不得再建立第二套相机写入循环。

### 3.2 数字键与组合键

- 人物与允许使用装备的状态保留 1/2/3 主副武器槽、4 近战槽、5 投掷物槽；
- 载具内仍允许未来使用直接数字键切装备，因此不把 1-5 独占给座位；
- Ctrl + 数字提交换位意图，且组合优先于 Ctrl 减速和数字装备切换；
- HUD 只显示当前载具实际存在的座位，不展示无效数字；
- Episode 和程序化输入使用相同的组合解析结果，不直接伪造座位状态。

### 3.3 复位、视角与一次性动作

- F、V、R、X、B、Q 翻滚、换位和武器槽切换按下沿触发；
- Backspace 复位使用长按或等价防误触策略，最终仍进入现有 reset 生命周期；
- LMB/RMB 的持续或按下沿由当前武器/能力说明声明；
- 输入焦点位于文本框、代码编辑器或表单时，不把字符键和 Backspace 送入玩法控制。

## 6. HUD 与 AI 语义

### 6.1 减速与刹车

同一对象可以同时存在 S、Ctrl 和 Space，但 HUD 必须显示不同职责：

| 输入 | 推荐语义 |
| --- | --- |
| S | 降低纵向速度；停稳后允许倒车，或直接表示后退需求 |
| Ctrl | 减速、制动或精细操控；人物上下文覆盖为蹲伏 |
| Space | 跳跃、上升、手刹、服务刹车或对象特殊动作 |

运行时字段可以暂时复用，UI 不得把三者都笼统显示为“减速”。

### 6.2 `boost` 与模式专用名称

| 当前模式 | 推荐显示名 |
| --- | --- |
| 地面车辆 | 加速 |
| 动力飞机 | 可选加力 |
| 滑翔类 | 牵引/助跑 |
| 潜艇 | 推进增强 |
| 飞龙 | 耐力冲刺 |
| 热气球 | 不暴露 `boost`；使用加热上升 |

底层短期可以保留 `boost` 兼容字段，但 AI-facing contract 应输出模式专用名称。

### 6.3 结构化控制说明

每个模式至少暴露：

- 当前 mode / archetype / subtype；
- `implemented`、`reserved` 或 `experimental` 状态；
- 物理入口与设备无关意图；
- 当前对象动作名称及轴正负方向；
- `hold`、`edge`、`toggle` 或长按；
- grounded、airborne、water、aiming 等有效状态；
- 被忽略或被组合键消费的输入；
- 观察轴是否同时派生当前对象的俯仰需求。

建议使用 `throttle`、`pitchDemand`、`yaw`、`roll`、`turretYaw`、
`lateralThrust`、`verticalDemand`、`wheelBrake`、`airBrake`、`launchAssist`、
`counterThrust` 等实际语义，不把 `forward`、`boost` 或 `roll` 原样当成所有模式的说明。

## 7. 相机跟随与移动端迁移

飞机、滑翔类、潜艇、飞船和飞龙进入三维运动后，相机默认跟随主体朝向。建议把响应拆为：

```text
yawFollowResponse    水平转向跟随，默认最快
pitchFollowResponse  俯仰跟随，默认较快
rollFollowResponse   横滚跟随，默认较弱
```

普通第三人称保持地平线稳定，不把主体横滚 1:1 写入镜头；第一人称或沉浸视角可增强
横滚跟随。跟随参数属于 CameraDocument 或公共相机配置，不放进车辆物理 spec，也不建立
新的相机控制循环。

移动端不是把键盘键码照搬成屏幕按钮，而是复用设备无关意图：

- 左摇杆映射纵向移动/速度和水平移动/转向；
- 右摇杆或拖动映射观察/瞄准轴；
- 三维对象从右侧垂直观察输入派生俯仰；
- F、Space、C、Q/E、Shift、Ctrl、技能和换位按当前对象生成必要虚拟按钮；
- 瞄准按钮映射 RMB 状态，右侧观察轴继续负责准星方向。

## 8. 实施顺序

### 阶段一：输入入口和运行时控制链路

- `config/input.ts` 与 `WorldKeyboard` 接入飞书矩阵中的公共键、鼠标键和组合键；
- `humanoid-runtime/input.ts` 按对象上下文分发意图，落实人物 Ctrl/C 蹲伏覆盖；
- 建立单一观察/瞄准轴，接通方向键、PC 瞄准鼠标、移动端右摇杆和手柄右摇杆；
- 三维对象只从一条明确路径派生俯仰，不让相机和对象各自重复监听物理键；
- 飞机、旋翼/倾转、滑翔类、飞龙、飞船、潜艇和热气球按目标语义适配；
- Ctrl + 数字组合优先于 Ctrl 与数字单键；
- F、Backspace、V 和技能边沿接入既有交互、reset、CameraDocument 与动作生命周期。

阶段出口：目标对象行的输入进入正确控制族，组合键不产生副作用，鼠标瞄准不成为移动端
运行时依赖，Episode 显式输入仍使用同一语义入口。

### 阶段二：提示、资产说明和虚拟按键

- [`input-guidance.ts`](../packages/three-world/src/humanoid-runtime/input-guidance.ts) 输出当前对象真实动作；
- [`shortcuts.ts`](../packages/preset-content/src/ui/shortcuts.ts)、Playground HUD、Creator discovery
  和资产 `hint` 读取同一份结构化控制说明；
- 移动端只创建当前对象需要的摇杆和按钮，不显示未消费键；
- 1/2/3、4、5 明确显示为装备槽，Ctrl + 数字显示为换位；
- 飞龙显示 LMB 喷火，飞船显示 A/D 转向，不继续传播旧文档语义。

### 阶段三：AI-facing 语义接口

在输入与 UI 稳定后，暴露模式专用动作、轴方向、输入形态、有效状态、忽略字段、组合消费
