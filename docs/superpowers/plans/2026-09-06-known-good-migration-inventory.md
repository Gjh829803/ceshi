# 历史基线上的迁移清单

2026-09-06。状态：梳理与设计，尚未迁移实现，也未启动下一轮生成。

目标分支 `codex/creator-known-good-baseline`，生成代码基线为 `03b8cb656c2e4ccf0770f50d8c09872c39259a48`。候选来源为 `codex/gpt6-world-agent-refactor`，截至 `029759dd`。用户认可本轮效果，要求先列出值得迁回的改动。本文不改变冻结 prompt、SDK、Creator、launcher 或原始生成案例。

## 结论与证据范围

先迁移有明确故障证据的实现修复及云端可靠性，再逐项验证会改变 Agent 工作方式的工具、示例和提示。按功能提取改动，不能整包 cherry-pick：例如相机提交同时改了 prompt/工具，UI 提交同时增加了较长说明，检查点提交同时改变了预算引导与静态合批。

本轮相同输入、相同历史 runtime 的两个任务均已交付。环岩约 24 分 51 秒，峡谷约 33 分 41 秒。原始交付的开场图分别保留了多层断环与连续岩壁、完整骑乘与分层台地。两例是有用的创作质量参照，不能据此证明所有图片都稳定，也不能单独归因于某个旧实现。

路线报告同时揭示基线缺口：环岩 4/4 目标到达；峡谷 3/5，两个高处目标未到达。峡谷报告仍为技术 `passed`，因此这个状态不能表示全路线通过。未到达也不能单凭这份报告断言物理上不可达，需要区分输入没走到、目标设置和真实道路问题。两例均不足以证明超过五分钟的有意义探索。

本次证据包含源码差异读取、历史运行记录及本轮云端真实交付/截图/键盘报告；未对下面任何候选补丁重新执行测试。历史测试证明其原分支的相应范围，不能当作迁入基线后的兼容性证明。

## 基线已经具备，不应重复重构

- Agent 用原生 Three 编写几何、材质、主体外形和场景逻辑；SDK 管理同一个物理世界、时钟、角色与可选跟随相机。
- WASD 移动、方向键转镜头、持续按 Shift 奔跑、每次新按空格跳跃，普通跳跃落地回到 idle/walk/run。
- 对象登记、移动/缩放/显隐、原型生成/移除、参数和动作、状态、几何替换、自定义运动意图，以及 NPC 移动/跟随/巡逻。低延迟控制不需要再造一套世界描述语言。
- G-bot 加载、骨架及标准动作复用。原版环岩已经做过保留骨架、定制外形；不必强制机器人外观或所有案例都复用 G-bot。
- 普通 HTML UI 可以独立于 Three canvas。完整的模型输出展示和帧对应协议是后来新增的能力。
- 装饰和物理障碍可以区分。小石头是否阻路首先取决于登记语义；不能把所有碰撞不适都当成缺少一套新 SDK。

依据：`packages/three-world/src/contracts.ts`、`input.ts`、`engine.ts`、`world.ts` 和历史生成源码。

第一项应先于整套相机重构：它有具体复现且不改变创作选择。`setCameraFollow()` 本来就存在，后来真正新增的是从当前镜头继承构图的行为；应作为下一步独立验证，不能把接口名称本身当成新能力。

现有评测页面的历史记录、生产状态和自动可玩展示已经在 Creator 外层继续使用。它们应保留，不需要再将旧页面或人工评审门槛迁回冻结 Creator。

## 值得保留，但必须拆开或重做

### 保存、可玩检查点、失败续跑分三步

自动保存最先做；成功 Preview 对应的可玩检查点其次；最后接入失败后基于源码继续。沿用 `cf13731e`、`0ac39d33` 中经过验证的归档与身份校验设计，但要适配本基线的 v1 交付合同，不能直接依赖后来 v2 的字段。

正常任务不增加恢复说明。只有实际续跑才附带简短交接：原图/请求、同一 SDK 锁、恢复的源码、已知失败、尚未完成事项。上次工具操作号、截图或报告不能当成本次新验证。确认父执行终止后最多一次模型续跑；正在运行、提交未知、停止中或用户取消不自动再开模型。已交付但下载失败只重取产物。可玩检查点可以立即试玩，WIP 源码只标为已保存。

不迁移“先交简陋版本”“不要继续打磨”等预算引导。续跑是故障恢复能力，不应提前改变正常创作投入。

### 去掉录像文件，保留目标与真实交互反馈

`41560172` 的方向符合用户此前需求，但不能整包迁回，导致有目标的路线反馈一并消失。建议把现有输入执行、位置/高度/目标距离和关键画面观察从录像编码中分离，供 Agent 自己用 Preview 检查通道、登高、远处空间、重置和相机。

不用固定录像时长、强制等待或人工评审。报告分别给出程序异常、输入是否执行、目标结果和未验证事项，不能用一个 `passed` 混在一起。声明的核心目标未达时，应将事实留给当前 Agent 判断、修正或明确报告；技术上可玩的版本仍能开放给用户。

本轮峡谷累计移动约 1,625 米，但没到两个高处目标，正好说明总路程/运行时间都不能替代目标验证。旧好案例的第一版结构早于第一次长录制，所以不能把录像本身当成好画质原因。移除录像对 Agent 完成行为的影响仍需单独实验。

### UI 与视频输出分层，协议交给宿主

保留 `695253f4` 的业务目标：原世界 canvas 输出白模视频，HTML UI 叠在最终模型视频之上，点击和键盘回到同一个世界输入系统。先迁移挂载与输入路由，再处理 `SourceFrameKey`、重置 epoch 和有帧映射时的锚点 UI。

Agent 只需要短小的 UI 挂载用法。网络传输、视频解码与帧映射由应用/服务端负责，不把整份视频协议塞进正常创作 prompt。缺少真实帧对应时不能用猜测延迟表示同步完成；源画面投影也不等于追踪视频模型生成的新物体。现有实现不代表已经完成视频模型端到端接入。

### 性能工具应允许原生 Three 特性继续工作

`0ac39d33` 新增的 `batchStaticMeshes` 有价值，但当前版本遇到自定义 shader/material hook 等会拒绝整组；此前 A/B 也出现过 `STATIC_BATCH_MATERIAL_UNSUPPORTED`。应先改为明确选择可合批子集，其余物体原样保留并返回处理摘要，不能为了使用辅助函数迫使 Agent 放弃材质或几何表达。

静态合批必须保留材质、层级与资源归属，不能跨独立可控制对象合并，也不能破坏三视图的完整代表。先测同源码的实际浏览器帧率、输入位移与渲染差异，再决定是否提供按需工具；减少 draw call 不等于所有卡顿解决。

### 示例和规划要求单独实验

旧 extensions 示例缺文件是缺陷，不应人为依赖 ENOENT 维持质量。但后来整套狐狸、信标、天空和桥的演示可能带来内容偏置。修复方向是按需返回一个能力的短例子，而不是向每个世界灌入一个完整演示游戏。资产复用展示骨架和动作能力即可。

“超过五分钟可探索、封闭空间要延展、首帧匹配”继续作为产品目标。强制 ImageGen 总图的 `e5a28a89` 不立即整包迁回：先让路线/高差/连通反馈可用，再独立验证总图是否真正指导实际世界。规划图漂亮或空间面积大都不能独自证明五分钟可探索。这一层若需要调整提示，只增加必要目标，不同时改视觉风格、人物简化或工具预算。

## 暂不迁移与尚需新设计的部分

- 不整体恢复后期长 prompt、重复时间提醒、抽象白膜说明、相反方向的强制精细渲染说明，以及全量能力演示。
- 不增加 assistant/human 的发布审批。用户要求分析时做质量分析，不把分析者变成生产依赖。
- 大世界物理预算、导航分区与复杂 NPC 碰撞需要另行设计和具体复现。旧版也存在相同预算，不应声称后期已经完成了可直接迁回的通用解决方案。
- Host 输出目录与 Agent 源码目录的写权限隔离是新工作。此前 A/B 发生过 Agent 改写报告，现有检测虽拒绝该交付，仍应让工具拥有结果写入权。它不靠更多禁止性 prompt 解决，也不伪装成已完成的迁移项。

## 每层如何判断是否保留

1. SDK 修复先在相同生成源码上复现和验证，保持场景、输入、prompt 不变。分别记录实现错误、渲染结构和操作体验，不依赖又生成一个不同世界来证明修复。
2. 影响 Agent 的能力、返回内容、示例或提示，每层只改变一项；固定模型、预算、工具包其余部分和原图。先用两张对照图定位变化，再用未参与调优的图片验证泛化。单次抽样不证明因果或普遍稳定。
3. 比较首版与最终的构图、地形层次、主体/关键建筑完整性、可探索空间和核心路线结果；不用“更慢”“调用更多工具”或“交付成功”代替质量。
4. 按改动运行针对性复现、相关完整检查和实际云端工具验证。每一层保留旧锁、原产物及回退点。生产页面随真实交付开放试玩，不新增人工审批。
