# Three SDK 单人骑乘增强设计

状态：实现、独立评审、最终整体检查，以及最终运行时的本地 Creator 骑马交付和独立 Episode 录制均已完成；已获准合入工作主分支，尚未发布。验证见[实施记录](../../reviews/2026-09-08-three-mounted-interaction.md)。

日期：2026-09-08。源码检查基线：`35d917114be362e616a5f2354141fbe0b85962f1`。

本次修订补充更新依赖、逻辑/视觉座位、碰撞查询组合和下马运动继承。
对照主流引擎官方文档的结论见第 11 节；这些设计约定尚不构成实现验证。

## 1. 目标与边界

当参考图包含人骑马时，Creator Agent 能从允许的马资产发现完整用法，
接入已有 SDK，并通过真实输入验证上马、骑行、下马和重置。

保留 `packages/three-world` 的 Training 实现，不新增 package。
人物绑定、坐骑运动、碰撞、输入、动画与相机仍由同一个 SDK 实例执行。
场景作者提供普通 Three 对象、地图、马的实例配置与视觉资源。

本设计是对现有实现的增强提案，不是另一份公开 API 声明。
实现时应同步修改[实际公共类型](../../../packages/three-world/src/contracts.ts)、
[Training 契约](../../../packages/three-world/src/training/runtime.ts)和
[SDK README](../../../packages/three-world/README.md)；遵守
[架构职责](../../three-sdk-architecture.md)及[生产边界](../../three-sdk-data-production.md)。

本轮范围是一个受控人物、每个坐骑一个座位、同一时刻骑乘一个实例。
新增的马专属登乘规则适用于地面 `mount` 模式；不自动改写船、飞行器等已有模式的规则。
允许场景放置同一马资产的多个独立实例。多人、多座位、拖挂、摔落布娃娃、
通用物理约束系统和普通世界/Training 世界的运行中切换均不纳入本轮。
专用上下马动作、缰绳与脚蹬 IK 留作后续视觉增强。

## 2. 当前实现与缺口

以下“已有”和“缺口”记录原设计基线；后续实现及实测结果见实施记录，不应将本表当作当前缺口清单。

| 能力 | 已有实现 | 本轮需要补强 |
| --- | --- | --- |
| 资产发现 | `training.horse` 在 Host 允许目录，携带 `training.spec`、`seat`、`characterPose`、碰撞包络和控制提示 | 马资产没有人物资产那样的专用接入指导及示例跳转 |
| 公开入口 | `world.execute` 路由 `training.enter / exit / input`；`world.training` 提供相应方法 | 说明命令应用、绑定生效和过渡完成分别意味着什么 |
| 上下马 | 检查状态、距离、速度和过渡互斥；下马寻找安全落点 | 上马按最近实例和距离选择，尚缺明确的登乘侧、遮挡和可达空间检查 |
| 人物绑定 | SDK 根据坐骑变换和 `spec.seat` 同步人物位置、朝向，切换人物胶囊启用状态 | 用真实人物和马验证偏移、姿势及整体碰撞包络 |
| 控制与运动 | 坐骑接管输入；`mount` 控制器执行前进、转向等运动 | 验证步行/骑乘切换的按键延续、重复交互和重置行为 |
| 查询 | `mountedInstanceId`、`transition.kind / remainingSeconds`、速度、落地状态及消息已存在 | 给出稳定的读取规则和结构化拒绝原因，不重复建设状态存储 |
| 姿势 | `TrainingCharacter` 使用坐姿基础及 `MountedRiderPose`，骨盆对齐座位 | 程序姿势不等于专用骑乘动作；近景效果需单独评审 |
| 验证 | 已有载具切换、运动、重置与 Episode 相关测试代码 | 需要实际人物与马组合的完整输入及画面证据 |

两个容易误用的既有行为：

1. `training.approach` 会把人物重定位到安全交互点，并非寻路或真实走近。
   它可以用于明确的初始化和调试，不能证明用户输入到达、登乘路径通畅或路线完成。
2. `training.enter / exit` 当前返回 `applied`，绑定已切换但视觉过渡可能还在进行。
   过渡时间已经可查询；不能把回执应用成功解释为整段动作播放完成。

## 3. 方案选择

| 方案 | 收益与代价 | 决策 |
| --- | --- | --- |
| 只补 Prompt 和示例 | Agent 更容易接入，但登乘边界仍由场景假设承担 | 作为工作的一部分，不单独作为完成标准 |
| 在现有 SDK 内补边界、指导和验收 | 复用时钟、物理、绑定和命令，改动集中且可验证 | 本设计采用 |
| 拆出独立骑乘包或通用关系系统 | 需要新的依赖和跨包生命周期约定，当前没有独立消费需求 | 本轮不采用 |

保留 `training.*` 命令和当前初始化方式。仅在降低职责混杂确有必要时，
将登乘条件计算抽成 `three-world/src/training` 内部模块；不为抽象而迁移
整个 Simulation，不引入第二套物理循环、角色根变换或相机写入者。

## 4. 职责分配

| 所有者 | 负责 | 不获得的权限 |
| --- | --- | --- |
| Creator Host | 冻结资产策略，返回允许的资产及用法，保存真实输入和交付证据 | 不通过放宽资产策略或录制门槛让场景通过 |
| 场景 Agent | 选用资源、创建地图和实例、配置座位与完整对象捕获、按公开接口发出意图 | 不写人物/马的受管根变换，不复制物理或动画循环 |
| TrainingRuntime | 路由命令、同步绑定和观测，协调输入、暂停、重置及 Episode 生命周期 | 不根据模型自述生成成功状态 |
| Simulation 与环境查询 | 检查进入/退出条件，提交控制状态切换，计算实际运动和安全位置 | 不把读取状态变成隐式传送 |
| 人物与坐骑视觉模块 | 骑乘姿势、骨盆对齐、马的步态展示 | 只写 SDK 允许的视觉子树；不改物理真值或相机 |
| Episode Host | 初始化片段并通过已有端口推进和记录输入 | 不重复实现骑乘、不把中途重定位当成运动 |

绑定身份始终使用场景 `instanceId`。资产 ID 只表示资源来源，不能用于
区分场景里的两匹同模型马；座位偏移沿用实例的 `spec.seat`，不再复制一份
会与它失去同步的权威座位表。

## 5. Agent 的接入路径

1. Agent 读取环境和冻结资产策略；搜索马或骑乘时，结果明确说明这是
   Training 骑乘资产，包含所需人物资源、控制方式、接入主题和示例入口。
2. 人物使用现有 `humanoid.source-101` 与 `TrainingCharacter` 接入。
   普通 `humanoid.source-101 + addCharacter` 不会因加载马 GLB 自动获得骑乘能力。
   指导应按场景需要选择人物，不把默认人物规则误读成禁止完整人物资源。
3. 最小骑马示例只依赖所需人物和马资源，提供平地、一个障碍和一个可下马区域。
   通过 `createWorld({training: ...})` 提供人物、地图和马实例，读取目录中的
   实际配置，不复制训练场全集或写死资源哈希路径。
4. 马的几何加载、步态视觉更新和人物姿势接入必须一起演示。
   使用 SDK 的资源及马步态视觉接口，由 SDK 统一采样马与骑手；
   `onVisualUpdate` 用于额外的、由场景拥有的视觉子树。
   不把只加载 GLB、马根节点位移或模型含动画条目当成步态已经接通。
5. 角色通过真实输入走到登乘位置，再上马、运动、减速、下马、继续步行。
   示例明确给出回执与过渡状态的读取方式，以及被拒绝后的检查步骤。

当人物或马被 Host 策略禁用时，返回资源不可用的明确说明；不提供无法运行的
示例，不自动扩大允许目录。相关指导复用当前发现、schema 和示例工具，
公开说明更新在 SDK README 的现有主题中，不新增专门的模型侧运行协议。

## 6. 登乘和退出条件

### 6.1 上马

一次上马请求先确定目标实例并完成全部检查，再提交绑定、碰撞状态和控制切换。
失败必须保留原人物位置、控制状态和碰撞状态。

检查覆盖：目标存在且可用；人物没有骑乘、正在切换、搬运或执行互斥动作；
马的速度满足现有上马限制；人物位于目标的有效登乘侧；人物到登乘点之间无阻挡；
登乘点的站立空间与支撑有效；座位及骑乘后的整体包络不侵入环境障碍。

复用现有环境查询和安全点计算，避免硬编码另一套几何或只用目标中心距离。
候选登乘点由实例尺寸与座位关系派生。距离、坡度、支撑等容差应复用现有
人物/环境配置，并由真实马夹具验证；实现不得无依据放大范围让案例通过。
检查路径时允许忽略目标自身预期占据的部分，但不能忽略墙、其他实例或场景障碍。

首版仍允许通过明确状态切换将人物吸附到座位；不承诺真实攀上马背的连续动画。
登乘侧与遮挡检查保证该简化不能变成隔墙、远距离上马。

### 6.2 下马

保留速度限制和安全落点选择。候选点必须同时满足支撑、人物空间与离开路径要求。
只有检查成功后才解除绑定并恢复人物独立碰撞；没有安全位置时保持骑乘并返回原因。
不能先解除绑定再尝试寻找位置，也不能失败后留下同时受两套控制的角色。

首版马的正常下马限定为地面低速状态：马已落地，满足现有速度限制，候选点具有
可供人物站立的支撑。空中、深水或没有可站立支撑时拒绝正常下马；紧急跳离不在本轮。

在成功提交的同一状态边界，一并确定人物位置、碰撞、朝向和初始速度：

- 位置使用刚完成空间与路径检查的落点，不能从视觉鞍点或旧缓存重新算一个不同位置。
- 人物恢复直立，水平朝向沿用马在提交时的逻辑 yaw；不继承马的 pitch、roll 或骨骼姿势。
- 初始速度继承马在提交时、经碰撞求解后的世界空间平移速度，写入实际人物运动控制器。
  地面法向速度由人物支撑/碰撞求解约束；不能只修改用于展示或查询的速度字段。
- 不将重定位到落点的距离除以时间当作速度，不累加马的视觉起伏，也不在每帧重复继承速度。
- 首版不叠加 `angularVelocity × seatOffset` 的旋转切向速度。这是地面低速骑乘的明确简化，
  不声称覆盖旋转平台、高速跳离或通用刚体分离；将来需要时再扩展运动契约。

解除绑定后，人物立即由自己的物理控制器处理继承速度、支撑和碰撞。
下马过渡仅限制新的主动步行输入，不能冻结重力和碰撞，也不能在过渡结束时突加
积攒的位移。马保持自己的运动求解；下马命令不隐式令马瞬间停住。

### 6.3 绑定与碰撞

骑乘期间继续由 SDK 同步座位变换、朝向及骨盆对齐，人物的独立运动胶囊停用。
当前坐骑碰撞包络必须能够代表实际骑乘组合需要避让的空间；真实模型夹具需覆盖
马头、骑手上身及低顶障碍。不增加第二个会与马互相推挤的动态人物身体。
不同尺寸通过实例配置与校准解决，不修改原资产来源或凭空声明像素级贴合。

### 6.4 逻辑座位与视觉鞍点

`spec.seat` 继续表示坐骑逻辑根坐标系内、以米为单位的固定位置；姿态沿用坐骑
逻辑旋转。它负责人物受管根变换、骑乘关系、初始化与物理空间判断。
逻辑根保持已声明的尺寸语义，模型缩放在初始化时归一到视觉子树和对应碰撞配置；
新增骑乘示例不得使用未同步碰撞尺寸的非均匀逻辑根缩放。

视觉鞍点只解决马的动画起伏与人物贴合：

1. 默认从同一帧的马渲染姿态和 `spec.seat` 派生视觉座位。没有骨骼鞍点的资产
   仍可使用这一方式，不强制重做现有模型。
2. 若资产需要跟随动画，使用经校准的命名骨骼/Socket，或已有步态适配器给出的
   同一帧视觉锚点。相对校准来自资产静止姿态；不另存可被场景随意改写的逻辑座位。
3. 先完成马的动画及骨骼矩阵更新，再读取视觉锚点；SDK 在允许的骑手视觉子树上
   对齐骨盆并施加骑姿。校正不能改人物逻辑根、碰撞包络、速度、grounded 或控制关系。
4. 视觉位移与旋转的允许范围依据实际步态夹具固定，必须处于骑乘组合预留的空间内。
   缺失明确声明的锚点、无效矩阵或越界校正应产生可诊断失败，不能静默使用上帧锚点。
   资产没有声明动画锚点时，使用默认固定座位属于正常路径。

物理检查不读取动画骨骼来改写座位真值。视觉评审分别测量逻辑绑定偏差与骨盆相对
视觉锚点偏差，避免把合法的步态起伏误报成物理漂移。动画鞍点适配是目标设计，
不能因当前存在 `MountedRiderPose` 就声称已经完成。

### 6.5 碰撞查询组合

登乘检查必须在同一逻辑状态下组合执行，不能以一条中心射线或一次 sweep 代替：

| 顺序 | 检查 | 失败处理 |
| --- | --- | --- |
| 1 | 固定目标实例和候选登乘侧，检查数值、世界边界及当前人体/组合包络的非法重叠 | 保持原状态，不先传送脱困再接受请求 |
| 2 | 起点、登乘站位/下马落点的人体体积重叠检查；上马最终组合空间检查 | 拒绝空间不足；允许既有接触容差内的正常贴地 |
| 3 | 沿显式登乘/离开路径做人体体积扫掠，包括变更高度的路径段 | 任一段被墙、低顶或其他实例阻挡即拒绝该候选 |
| 4 | 验证站立点的支撑高度、坡度与允许介质 | 拒绝悬空、过陡或本轮不支持的介质 |
| 5 | 提交前确认目标、碰撞查询状态与候选仍有效 | 状态变化则重新检查，不提交旧结果 |

实际查询顺序可短路优化，但每类条件必须被验证。起终点重叠与扫掠分别验证；
射线只可用于支撑或辅助信息，不能证明人体能通过。改变方向或朝向的候选应使用
对应姿态的人体包络，不能仅扫一条无体积线段。首版路径是明确的几何可达性检查，
不等同于专用攀登动画的骨骼扫掠。

过滤规则由 SDK 控制：仅排除请求人物自身与目标坐骑的预期内部附着部分。
环境实体、低顶和其他坐骑/人物不能被一起排除。普通触发器不作为实体墙体；
水、禁入区和交互语义仍按对应规则单独判断。停用人物运动胶囊不代表关闭所有
未来可能存在的受击或交互检测；本轮也不新增受击系统。

现有 [EnvironmentQueries](../../../packages/three-world/src/training/environment/queries.ts)
的环境过滤会排除已注册 actor collider，因此必须显式补查其他实例的实际包络，
或使用限定范围的查询过滤；不能直接复用过滤器后宣称已覆盖动态实例。
不得为登乘查询修改全局碰撞组、关闭其他对象碰撞或让查询留下临时物理状态。
检查与状态提交之间不跨异步等待；成功提交后同步碰撞和查询可见状态。

实现前核对当前安装的 Rapier 查询语义，包括初始重叠、接触边距、传感器过滤和
查询数据更新时机，并保留针对性复现。不能把 Unity 的查询参数或行为直接照搬。

## 7. 命令、状态与生命周期

首版保留 `training.enter / exit` 的 `applied` 语义：检查成功后，绑定与控制状态
已经原子切换，过渡开始。无需为这两个命令新增一套异步操作系统。

| 语义阶段 | 从现有状态判断 | 操控行为 |
| --- | --- | --- |
| 步行稳定 | 无骑乘实例，过渡剩余时间为零 | 人物响应步行输入 |
| 上马过渡 | 已绑定目标，进入过渡剩余时间大于零 | 不提前推进坐骑 |
| 骑乘稳定 | 已绑定目标，过渡剩余时间为零 | 坐骑响应输入 |
| 下马过渡 | 已解除绑定，退出过渡剩余时间大于零 | 限制主动步行，继续人物物理及继承速度的处理 |

阶段由现有状态解释，不另存一份 phase 真值；表中操控行为是本轮需验证并固定的约定。
判断完成以剩余时间归零为准，
不能只看 `transition.kind` 或命令回执。若未来引入可取消的连续上下马动作，
再评审如何接入现有 `world.operations`，不在本轮悄悄改变返回类型。

拒绝原因使用现有回执错误结构表达，至少区分目标不可用、距离/登乘侧不满足、
遮挡、空间不足、速度过快、人物动作互斥、过渡中和没有安全下马位置。
机器判断不依赖中文 `message` 的文本匹配。具体错误码随实际契约与测试维护，
本草案不另列一套可能脱离实现的 API 枚举。

暂停不推进过渡；恢复后按原 SDK 时钟继续。交互键沿用边沿触发，过渡期间的
重复请求不会排队造成再次上下马。同一命令身份复用既有去重规则。
移动键保持按住时，过渡结束后由新控制对象响应；过渡期间不缓存补发运动，
不能发生一帧双重运动。重置清除这些按键状态。

重置清除过渡、旧输入和骑乘状态。常规 reset 沿用现有 Training 的未骑乘起始状态，
保留当前地图和有效配置的既有语义；Episode 片段初始化可以显式从已骑乘状态开始。
Episode 持有时钟期间，普通命令不能绕过租约推进状态。销毁后不得有绑定、视觉或
输入回调继续写旧对象。相机保留同一个 SDK 写入者，覆盖开场到首个输入和重置后
重新跟随的连续性。

### 7.1 固定模拟与渲染更新依赖

本轮保留一个 60 Hz 模拟时钟；显示刷新和录制帧率可以不同。
阶段顺序是 SDK 的内部依赖，不通过新增作者侧帧循环实现。

| 阶段 | 必须完成的工作 | 可写状态 |
| --- | --- | --- |
| 固定模拟步 | 消费输入/命令；检查并提交控制切换；求解马与人物运动及碰撞；同步逻辑座位；记录当前 tick | 物理状态、绑定关系、逻辑根和逻辑快照 |
| 渲染采样 | 从同一对前后 tick、同一个插值系数取得马与人物显示姿态；绑定关系使用当前离散状态 | SDK 持有的显示姿态，不能反写模拟 |
| 马的视觉更新 | 依同一显示样本计算步态，更新视觉子树、骨骼及矩阵 | 马的视觉姿态 |
| 骑手视觉更新 | 从该帧逻辑座位或动画鞍点计算骨盆位置和骑姿 | 人物视觉子树；骑乘显示根位置从马的同帧姿态派生 |
| 相机与捕获 | SDK 相机读取已经就绪的目标显示姿态并完成避障，再渲染/捕获 | 相机；媒体与显示元数据 |

骑手不能独立插值到一个与马不一致的位置；对马的显示姿态只采样一次，再派生
骑手绑定姿态。逻辑相机障碍查询仍读取物理世界，显示目标位置与物理样本的关系
必须明确，不以视觉骨骼位置冒充运动证据。保留 authored/follow 的现有切换职责。

上马、下马、重置、地图替换和 Episode 起点重定位都切断旧显示历史；
不能跨绑定身份、实例或重定位进行插值。暂停后重复显示/捕获同一时刻不得额外
推进动画、过渡或模拟。视觉更新按样本时间计算，同一逻辑 tick 的重复捕获不能
把 `dt` 再累加一次。低帧率补多个模拟步时，每个输入边沿仍只消费一次。

现有 [PresentationState](../../../packages/three-world/src/training/presentation.ts)
提供前后状态、插值和重定位清理的可复用逻辑，但当前 `TrainingRuntime.sync`
在模拟步中先更新人物动画、再调用通用视觉回调；仅有该辅助类不证明上述整条
显示链已经接通。实现应核对并复用它，或在现有 SDK 阶段中完成同等职责，
明确马视觉 → 鞍点 → 骑手 → 相机的依赖，不能依赖回调注册顺序碰巧正确。

Episode 使用 Host-only 端口请求准确的模拟时刻；录制样本不能混入实时 RAF
累加器的剩余时间。若两个模拟步之间需要显示插值，时间由现有捕获调度明确给出，
马、人物和相机共用它；状态 trace 继续保留实际模拟 tick，视觉插值不冒充新物理帧。

## 8. 验收与证据

技术交付成功、骑乘专项验证通过、视觉评审通过分别记录。
骑乘专项测试不把新的语义门槛塞进所有 Creator 场景的通用提交规则。

| 层次 | 必须覆盖 | 通过依据 |
| --- | --- | --- |
| 发现与文档消费者 | 搜索马/骑乘、精确描述、人物依赖、受限策略、示例入口 | Agent 能从返回结果找到允许且可执行的完整接入路径 |
| SDK 条件与状态 | 距离、隔墙、低顶、速度、互斥动作、重复请求、安全/无安全落点、暂停、重置 | 成功原子切换；拒绝不改变受管状态；无重复输入或双重运动 |
| 实例与资源 | 两匹同资产马、不同朝向、实际人物与马、座位和包络 | 仅目标实例被控制；实际绑定与资源身份一致 |
| Creator 浏览器 | 真实走近、上马、骑行转向、障碍、下马、步行、重置 | 同会话实际输入、状态、预览与录像一致；禁止用 approach 替代走近 |
| Episode | 显式骑乘起点、输入运动、重复片段初始化、录制独占时钟 | 起点身份正确，运动由输入产生；重置无旧过渡或旧帧污染 |
| 视觉评审 | 侧视/正视/运动镜头、骑手和马整体三视图 | 无明显悬浮、座位滑移、身体穿插；程序姿势限制明确记录 |
| 更新依赖 | 30/60/120 Hz 显示，低帧率补步，连续转向，暂停重复捕获 | 相同固定输入得到相同模拟状态；马、骑手和相机无相差一帧；显示不额外推进模拟 |
| 视觉锚点 | 固定座位、有效动画鞍点、声明锚点缺失、转向及步态起伏 | 同帧贴合；无历史锚点复用；视觉校正不改变逻辑位置或碰撞结果 |
| 查询边界 | 初始重叠、终点空但路径隔墙、低顶、其他马阻挡、触发器与实体墙混合 | 每类查询和过滤按约定生效；拒绝不移动实体、不遗留临时 collider |
| 下马继承 | 停马、低速直行/转向下马，落点后方障碍，过渡中暂停/重置 | 速度进入真实人物控制器且只继承一次；朝向直立；物理继续而主动步行按约定受限 |

绑定验收同时量测人物相对座位变换和骨盆对齐偏差，并检查画面；不能只断言
`mountedInstanceId` 非空。运动验收检查马的实际位移、方向、碰撞和输入关联，
同时观察步态与速度是否匹配。容差来自实例尺度和既有数值精度，固定在测试夹具中，
不得在运行结果不理想时扩大容差或修改目标。

Creator 使用 v0.2 当前世界、当前输入计划的完整真实录制；计划覆盖核心功能与动作结果，输入、活动及视频时长为有限正值，录制长度由功能覆盖决定。
Episode 使用自己的录制端口及证据，不能拿 Creator 录像替代 Episode 验证。
媒体、执行日志、真实测试图片及案例数据保留在 Git 外部。

## 11. 主流引擎做法与本项目取舍

官方文档对照日期：2026-09-08。以下资料支持设计原则，不是本项目获得行业认证、
跨引擎兼容或运行验收的证据。具体骑乘玩法仍需要应用层组合与验证。

| 参考 | 官方机制 | 对本设计的含义 |
| --- | --- | --- |
| [Unreal Skeletal Mesh Sockets](https://dev.epicgames.com/documentation/en-us/unreal-engine/skeletal-mesh-sockets-in-unreal-engine) | 命名附着点，明确保持相对/世界变换或吸附的规则 | 座位附着是常见机制；固定吸附是明确选择，不能描述成连续上下马动画 |
| [Unity Transform.SetParent](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Transform.SetParent.html) | 显式选择是否保持世界变换 | 必须明确坐标系、旋转和缩放语义；本 SDK 不必真的改父子关系才能实现绑定 |
| [Godot BoneAttachment3D](https://docs.godotengine.org/en/stable/classes/class_boneattachment3d.html) | 骨骼更新后复制或覆盖骨骼变换 | 动画鞍点必须在对应骨骼样本就绪后读取，不能用上一帧矩阵 |
| [Unreal Actor Ticking](https://dev.epicgames.com/documentation/en-us/unreal-engine/actor-ticking-in-unreal-engine) | Tick 分组和显式依赖用于安排物理及显示更新 | 一个时钟之外仍需明确阶段依赖；不照搬引擎内部 Tick 分组名称 |
| [Unity Rigidbody interpolation](https://docs.unity3d.com/6000.0/Documentation/Manual/rigidbody-interpolation.html) | 区分物理姿态和显示插值，物理系统管理相应变换 | 逻辑位置与显示样本分开；骑手和相机共用马的显示时间 |
| [Unity CapsuleCast](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Physics.CapsuleCast.html) | 体积扫掠、层和触发器过滤；文档明确其初始重叠检测限制 | 不能用一次 sweep 替代所有空间检查；实际实现必须核对 Rapier 语义 |
| [Godot CharacterBody3D](https://docs.godotengine.org/en/stable/classes/class_characterbody3d.html) | 离开移动平台时的速度处理具有明确策略 | 下马速度继承必须成为约定，而非视觉附着解除后的偶然结果 |

本项目保留单座位、`applied` 回执、固定逻辑座位、程序骑姿和低速下马仅继承
平移速度，属于当前范围与兼容性取舍。文档对照只能确认总体原则相容；
第 8 节的实际模型、物理和录制验收通过后，才能判断这些细节在本项目中是否可靠。
