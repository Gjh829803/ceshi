# 资产提交与合并流程

面向资产生产同事。提交的是一份**可接入的资产包**：资源文件、使用说明，以及对应的资产登记；有新行动模式时，再附实现或明确的接入需求。

## 1. 从目标分支另开资产分支

拉取 `codex/three-sdk-data-production-20260907` 最新版本，从它新建自己的资产分支。PR 的目标分支也选它，不直接推送共享分支。

一个资产包或一类能力一个 PR，不混入无关清理、目录重构和评测运维改动。

## 2. 提交资产包

统一放到 `assets/three-creator/<资产包>/<资产ID>/`：

| 内容 | 需要提供什么 |
| --- | --- |
| 模型与必要依赖 | 可直接加载的自包含 GLB；有动画时附真实片段和对应模型 |
| `README.md` | 资产 ID、用途、尺寸/朝向、关联的行动模式、使用条件和已知限制 |
| 来源与授权 | 来源说明、许可证及随包交付的授权材料 |
| 行动模式 | 说明复用哪个已有模式；若是新能力，附代码改动，或明确交给 SDK 接入同事完成的需求 |

资产以白模为主，仅少量关键标志物加颜色；主体尽量复用提供的资源，不额外做装饰。

## 3. 在同一个 PR 中完成登记

| 文件 | 修改内容 |
| --- | --- |
| [资产目录](../assets/three-creator/asset-catalog.json) | 增加本资产条目：ID、资源路径、实际哈希和字节数、依赖、能力配置与限制。按现有条目填写，保留其他资产 |
| [资产策略](../config/three-creator/asset-policy.json) | 将新 ID 加入 `allowedAssetIds`，保留现有默认主体和策略 |
| 使用说明或示例 | 提供可复用的接入方式；需要 Agent 直接获取的新示例，由接入同事同步工具入口和运行包配置 |

复用已有行动模式，通常只需模型、配置和登记。新增行动模式，需要同步对应 SDK 实现及 Creator、Episode 接入；只填写模式名称或上传动画不会自动获得能力。资产生产与代码接入由不同同事负责时，在 PR 中写清交接人和待完成项。

## 4. 提 PR 时写清楚这些

```text
资产 ID / 资产包：
新增或更新的资源：
对应行动模式：复用已有 / 新增
使用条件与已知限制：
来源与授权：
验证结果及示例或预览链接：
需要接入同事完成的事项（如有）：
```

提交前确认资源能加载、Agent 能查到、声明的主要能力能实际使用。检查范围随改动决定，没有固定录制时长要求。

## 5. 合并后发布

由接入同事审查资源、登记和能力绑定；共享目录发生冲突时，保留双方资产条目，按最终文件更新哈希。合入目标分支后，由发布侧重新打包，供新任务使用。**文件合入 Git 不等于线上运行包已经更新。**

具体接口按需查阅 [SDK 指南](../packages/three-world/README.md) 和[运行包指南](../deploy/three-creator-runtime/README.md)。
