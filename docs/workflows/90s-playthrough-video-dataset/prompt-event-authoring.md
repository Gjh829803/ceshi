# Gemini visual-event authoring

大型视觉事件由独立 Gemini 3.5 Flash Event Director 生成，不属于 Playthrough Planner。
一次请求按固定顺序输入：

1. capture 00 完整 30 秒白膜视频 + 对应样式首帧；
2. capture 02 完整 30 秒白膜视频 + 对应样式首帧；
3. capture 04 完整 30 秒白膜视频 + 对应样式首帧。

三个视频都设置 `VideoMetadata(fps=0.25)`。Gemini 需要同时比较整组内容，一次输出五条
事件，分布 2 / 2 / 1。这样事件可以在组内去重，避免每段独立请求都产生相同天气或
发光效果。

事件必须利用当时真实可见的主体、标志物、材质、天气、地貌或文化语境，变化明显、
有趣、合理且具有视觉渲染力。每条描述变化前、传播过程、完成状态、声音与保持不变的
空间关系；同一视频的第二条承接第一条完成状态。事件不得依赖跳跃、转向、攻击或按键，
不得改变镜头、路径、碰撞、地形结构或持久实体数量。

五条事件中恰好一条由 Gemini 设计为全场景视觉重构：把同一世界整体转化为另一种
强烈、合理的环境状态，覆盖地表材质、既有物体表面、天气、空气和光照。它是同一张
地图的整体换肤，不是换地图；地形高度与轮廓、空间拓扑、可通行区域、水岸边界、
碰撞、物体锚点、主体运动和相机均保持不变。其余四条仍按场景自由发挥不同类型的
大型变化。示例只表达变化尺度，不作为固定候选或关键词规则。

创意不使用具体效果黑名单。系统只要求五条互不重复、强场景关联，不因曾经出现过某个
圆环、风暴或光效就机械拒绝。最终好坏由 Studio 人工审核。

Host 在 Gemini 返回后补齐稳定 ID、时间槽、`actionCoupling` 和规范化 `eventPrompt`，
并绑定实际 Trace 中的五个 Prompt Marker。完整模板位于
`config/prompts/episode-visual-event-director.zh-CN.md`。
