# Seedance Prompt Event 写作合同

## 1. 定位

`SeedancePromptEvent` 是最终生成视频必须在指定时间渲染的一次视觉事件。它不是：

- 白膜 Runtime 命令；
- 世界结构修改请求；
- UI 中显示的聊天文字；
- 关键词标签或供另一个 Agent 猜测的简略 Brief；
- 可以被 Segment Prompt Composer 自由改写的灵感描述。

事件原文是一级数据制品。Planner 完成后保存内容 Hash；后续 Composer 只能加入引用职责、
白膜权威和全局限制，不能删除、弱化或改变事件语义。

## 2. Codex 写作证据

Codex 写每条 Event 前必须同时看到：

- Scene Brief、移动模式和完整视觉目标；
- 用户参考图和实际白膜进入首帧；
- 俯视规划、Runtime Snapshot、主体 Capability；
- 侦察截图、轨迹和碰撞/可达空间摘要；
- 完整 90 秒输入与相机剧本；
- Event 选中 Tick 前后至少数秒的动作、主体朝向、镜头方向和可见地标。

事件必须引用这些证据中的现有目标和可见关系。只读到场景标题、没有查看事件时刻动作与
画面的 Codex 不得产出正式 Event。

## 3. 写作顺序

1. **定位事件帧**：确定 Segment 相对秒数，并读出该时刻前后玩家正在执行的输入、速度、
   跳跃/技能状态、镜头视角和画面中可见目标。
2. **选择现有作用对象**：只能选择当前画面或世界中已声明的主体、标志物、环境表面或
   渲染层。不得为了让 Prompt 更精彩而新增人物或物体。
3. **先用熟悉名词命名主要变化**：普通人必须能用一个具体、熟悉的名词短语说清整个
   Event，且它必须由实际场景主题推导。优先熟悉天气、地表/材质状态、物理现象、庆典或
   主体变身；不要为了新奇拼接抽象视觉设计。三个 Event 不应是同一句模板只替换颜色/
   名词；场景不支持多样变化时宁可保持简单，也不拼接多个事件。
4. **检查动作兼容**：视觉变化不能要求白膜视频中不存在的主要姿态。若事件语义需要一次
   明确释放动作，Playthrough Plan 必须在相同时刻预留兼容输入；否则改写事件。
5. **写时间曲线**：明确开始秒数、渐变/爆发过程、达到峰值或完成的时间、之后保持还是
   自然消退。禁止“随后发生变化”这类无时间锚点表达。
6. **写空间与物理表现**：说明效果贴附、传播、照亮、遮挡或反射在哪些现有表面上，以及
   哪些区域必须保持清晰可见。视觉效果可以穿过开放空气，但不能变成新碰撞体。
7. **写连续性限制**：身份、动作、移动速度、镜头、场景布局、标志物位置和遮挡顺序继续
   服从白膜视频。
8. **写同步声音**：只写与事件可见过程同步的效果音/环境响应；禁止音乐和人声。
9. **自审**：对照禁止项、需求示例复用、动作冲突和时间歧义，失败则在同一个 Codex Job
   内重写。

## 4. 自然语言事件块结构

最终 Event 采用可直接放入 Seedance Prompt 的中文自然语言。可以使用下面的字段顺序，
但方括号必须被场景事实替换，且输出不能保留占位符：

```text
事件时间：在本段第[精确秒数]秒开始，用[过渡时长]秒完成主要变化；随后[保持/增强/消退方式]。
事件目标：[现有目标的明确自然名称，以及它在当前画面中的位置或状态]。
变化过程：[从当前外观到目标外观的连续可见过程；材质、光照、粒子/体积、方向、范围、强弱与表面响应]。
动作与镜头：[继续严格执行白膜中的具体动作、速度、朝向和镜头运动；事件如何与已存在动作同步]。
完成状态：[变化完成后画面中能够明确观察到的稳定结果，或消退后的结果]。
声音：[只包含与过程同步的环境/动作效果音；无音乐、对白、旁白或歌声]。
限制：[保持身份、数量、空间布局、碰撞、路线、遮挡和相机；无新增人物/物体、切镜、UI、文字或水印]。
```

这是一种语义结构，不要求机械输出完全相同的标题；重要的是九项信息都在自然语言中闭合。
不设置固定字数。过短会缺少可执行细节，过长会引入互相竞争的事件，审核以信息闭合和单一
主事件为准。

## 5. 与游玩剧本的耦合

Event 不能脱离白膜动作单独创作：

- 材质、光照、环境表观和后处理变化可以在正常移动期间发生，但不得改变移动结果。
- 需要主体明显发力、挥动、跳起或触发能力的事件，必须和剧本中真实存在的离散动作同步。
- 若主体不支持对应动作，Codex 必须选择不依赖该动作的场景相关事件，不能要求 Seedance
  伪造动作。
- Event 前后仍保留足够时间观察变化；随机时间只决定窗口中的发生点，不能让事件被切片
  结尾截断。
- 镜头可以继续按白膜观察效果，但 Event 不能要求新增推拉、环绕、切镜或改变焦段。

Playthrough Planner 因此需要联合规划“操作 + 镜头 + Event”，而不是先写一条固定操作
轨迹，再独立随机填三句 Prompt。

## 6. 熟悉概念不是固定词库

熟悉的天气、自然现象、庆典和主体变化类型可以帮助 Agent 理解“普通人一眼能命名”的
边界，但不能成为随机词库、固定 Prompt 或 names-swapped 模板。Agent 必须先看当前世界
证据，再选择真正匹配的熟悉概念。Agent 得到的是：

- 当前世界证据；
- 允许的变化范围；
- 禁止的结构操作；
- 写作合同；
- 当前动作时间线。

审核时比较三条 Event 的目标、过程和视觉语言；若它们明显来自同一通用模板、与 Scene
Brief 无关，或者需要用“能量环、磁力帘幕、几何天幕”等动效术语才能解释，则退回同一
Codex Job 重写。

## 7. 硬拒绝条件

以下任一情况使 Event 不可提交给 Seedance：

- 没有准确 Segment 相对时间或没有过渡过程；
- 目标无法对应现有主体、视觉目标、环境表面或渲染层；
- 要求新增/删除人物、物体或结构；
- 要求改变地形、碰撞、路线、标志物位置或相机轨迹；
- 要求白膜中不存在的主要动作，且没有同步的操作输入；
- 只写抽象审美词，没有可观察的开始、过程和完成状态；
- 使用天空圆环、巨型光环、传送门、抽象几何天幕、磁力帘幕、能量丝带、悬浮符号、
  任意光隧道、通用粒子流或无原因调色，且用户/来源场景没有明确要求这种现象；
- 同时堆叠多个独立主事件；
- 与 Styled 首帧、三视图或用户参考中的身份/材质基线冲突；
- 复用需求示例或生成与场景无关的通用效果；
- 包含音乐、人声、字幕、Logo、UI 或水印要求。

## 8. Segment Prompt 组装

最终发送给 Seedance 的每段 Prompt 使用固定优先级：

1. `@视频1`：30 秒白膜分段，是根轨迹、相机、时序、空间和遮挡唯一权威。
2. `@图片1`：主角 Styled 三视图，是主角身份、结构、材质和细节权威。
3. `@图片2`：该分段 Styled 首帧，是事件发生前的环境、灯光和开场画面权威。
4. `SeedancePromptEvent`：仅在指定相对时间改变被声明的视觉状态。
5. 全局限制：允许按实际运动方式补全自然肢体动作和过渡帧，但不得改变根轨迹、速度阶段、
   转向/起落结果或镜头；无新增人物/结构、无切镜、无 UI、无音乐/语音。

生产模板版本锁定为 `worldkit-reference-video-relaxed-action@1`。配置、Composer 和 Provider
任务输入身份必须记录同一版本；版本不一致时流水线直接失败，不能沿用旧缓存。

Composer 必须原样携带 Event 的以下字段：开始秒数、目标、主要变化、过渡时长、动作耦合、
完成/消退状态和声音。允许为引用图片补充明确名称，不允许把高细节 Event 压缩成一句摘要。

## 9. 质量评测

### Prompt 提交前

- Grounding：每个目标可回溯到 Scene Brief/Visual Target/事件帧证据。
- Temporal completeness：开始、过渡、完成/消退均明确。
- Motion compatibility：不与白膜动作和相机冲突。
- Scope control：一个主事件、无结构变化、无新增人物。
- Scene specificity：换到另一个世界后不能仍然原样成立。
- Renderability：描述可见、连续、具方向与表面响应，不依赖抽象概念。

### 视频生成后

- 记录人工或视频理解模型观察到的实际 onset、peak、ending 时间；
- 比较计划时间和实际时间偏差，但首期先记录分布，不在未校准前设任意硬阈值；
- 检查事件前身份稳定、事件过程连续、事件后无闪烁/材质跳回；
- 检查玩家动作、相机和空间没有被 Event 改写；
- 检查声音与事件同步且无音乐/人声。
